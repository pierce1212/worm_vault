### 3.6 LevelIMMO 算法与 PIN

| ID | 需求 | 强度 | 来源 |
|---|---|---|---|
| IMM-001 | 涉及防盗的 ECU 应实现文档 3.3.1 给出的 `calcKey` 自定义算法。 | 条件强制 | 3.1、3.3.1 |
| IMM-002 | LevelIMMO 的 requestSeed/sendKey 子功能应分别为 `0x05/0x06`。 | 强制 | 嵌入矩阵，原文第 2 页 |
| IMM-003 | 算法输入 `v` 是 Seed 的地址，计算结果 Key 也应写回 `v` 指向的存储区。 | 强制 | 3.3.1 Note，原文第 6 页 |
| IMM-004 | 算法内部应使用 4 个常量字：`BE355A5C`、`D6952BBE`、`355A5CD6`、`952B784E`，拼接值为 `0xBE355A5CD6952BBE355A5CD6952B784E`。 | 强制 | 3.3.1 代码及 Note |
| IMM-005 | 当 `PINP != NULL` 时，算法应执行 `k[0] ^= PINP[0]`，将 PIN 混入第一个常量字。 | 强制 | 3.3.1 代码，原文第 5 页 |
| IMM-006 | 算法应使用 `DELTA = 0x9e3779b9`、`n = 2` 和 `q = 58`。 | 强制 | 3.3.1 代码 |
| IMM-007 | 算法应逐字执行文档所给 `MX` 公式及 58 次循环更新逻辑；不能用未经等价性验证的替代算法。 | 强制 | 3.3.1 代码 |
| IMM-008 | 对 `securityAccessType = 0x05`，文档给出的调用方式为 `calcKey(&SeedOrKey, &PIN)`。 | 指定调用方式 | 3.3.1 Note，原文第 6 页 |
| IMM-009 | PIN 必须“一车一 PIN 码”。 | 强制 | 3.3.2，原文第 6 页 |
| IMM-010 | PIN 应由整车下线电检设备写入 ECU。 | 强制 | 3.3.2，原文第 6 页 |

为防转录遗漏，源文算法如下。该代码存在类型、端序和 C 语言未定义行为风险，不能在澄清 Q-017～Q-022 前直接视为跨平台可移植实现。

```c
#define MX (z>>5^y<<2) + (y>>3^z<<4)^(sum^y) + (k[p&3^e]^z)
long calcKey (long* v, long *PINP)
{
    long k[] = {0xBE355A5C, 0xD6952BBE, 0x355A5CD6, 0x952B784E};
    long n = 2;
    unsigned long z=v[n-1], y=v[0], sum=0, e, DELTA=0x9e3779b9;
    long p, q;
    if (PINP != NULL)
    {
        k[0] ^= PINP[0];
    }
    q = 58;
    while (q-- > 0)
    {
        sum += DELTA;
        e = (sum >> 2) & 3;
        for (p=0; p<n-1; p++)
            y = v[p+1], z = v[p] += MX;
        y = v[0];
        z = v[n-1] += MX;
    }
    return 0;
}
```

## 4. 术语与非需求性说明

| 术语 | 原文含义 |
|---|---|
| 对称算法 | 使用相同密钥执行加密或解密，例如 AES。 |
| MAC | 使用对称密钥检测数据是否发生意外或有意修改的数据校验和。 |
| Seed | 真随机数或伪随机数产生器的输出。 |

文档将 0x27 流程描述为“单向挑战应答鉴权”：客户端证明其掌握预共享密钥，但文档没有要求 ECU 向客户端证明身份，因此不是双向认证。

## 7. 建议的验收证据

本节是为落实原文需求而整理的验证建议，不是源文新增要求。

- 需求到设计、代码、诊断规范和测试用例的双向追踪矩阵。
- Level1/LevelFBL 的 RFC 4493 单元测试、本文两个测试向量及 ECU-Tester 联调记录。
- LevelIMMO 的奇瑞官方测试向量、固定宽度参考实现、不同编译优化级别/不同端序的一致性结果。
- TRNG/DRBG 设计说明、熵源健康测试、实例化/重播种/掉电恢复策略和 Seed 不重复性测试。
- SE/HSM 密钥对象属性证明：不可导出、访问权限、调试口保护、生命周期状态和审计日志。
- 无安全硬件方案的威胁分析、密钥封装/混淆设计、完整性参考值保护及篡改测试。
- 产线密钥/PIN 灌入流程、端到端加密、人员分权、日志脱敏、失败回滚和泄露应急演练证据。
