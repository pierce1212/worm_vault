从一帧 CONNECT 看懂 XCP

这一课只拿下一件事：看到总线上的 FF 00，你能解释它如何进入本项目代码，并预测 ECU 的 8 字节响应。

完成标准

不看答案，说出请求/响应 CAN ID、首字节为什么都是 FF、响应里的 05 和两个 08 分别表示什么。

1. 先建立一个不会塌的心智模型

XCP 是主从式、面向 ECU 内存的测量与标定协议。标定工具是 Master，ECU 是 Slave。协议层定义命令和数据语义；CAN 只是本项目选择的传输层；A2L 则告诉工具“变量叫什么、在哪个地址、如何换算、该 ECU 支持什么 XCP 能力”。

主从模型、CTO/DTO 与内存访问定义见 ASAM 官方 XCP Wiki。术语可随时查阅核心术语速查。

2. 本项目的 CONNECT 请求

工具在 CAN ID 0x332 上发送：

FF00000000000000
CONNECTnormalpadpadpadpadpadpad

FF 是 Command PID：在 Master→Slave 的 CTO 中表示 CONNECT。第二字节 00 是 normal mode。CAN DLC 可以是 8，但 XCP 命令的有效长度只要求前 2 字节。

4. 预测本项目的响应

由生成配置和命令实现可预测 ECU 在 CAN ID 0x333 返回：

FF05C00808000101
RESRESOURCECOMMMAX_CTOMAX_DTO LEPL verTL ver
字节推导
FFSlave→Master 方向中，FF 是正响应 PID；同一个数值因方向不同具有不同语义。
050x01 CAL/PAG | 0x04 DAQ。本项目未启用 STIM 与 PGM。
C0支持 GET_COMM_MODE_INFO（bit 7）和 Slave Block Mode（bit 6）；Intel 字节序使 bit 0 为 0。
08MAX_CTO = 8。
08 00MAX_DTO = 8，以 ECU 的小端字节序传输 16 位值。
01 01协议层与传输层主版本都为 1；详细配置版本为 1.2。
关键辨析：A2L 不是通信协议，也不在每帧 CAN 报文中传输。XCP 栈负责按地址读写；A2L 让工具知道该读写哪个地址，以及怎样把原始字节解释成人能理解的量。
