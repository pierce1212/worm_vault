# 2. 定义工作流和验收标准
在需求探索阶段就定义上线所需的证据，此时客户正在帮助你确定成功意味着什么。

- **GOV.UK - 需求探索阶段如何开展** - 从这里开始学习如何界定问题、理解用户与约束，以及判断项目是否应继续推进。
    
- **Anthropic - 揭秘 AI 智能体评估** - 利用其中关于评估结构和评分器的章节，将客户案例转化为具有明确成功标准的测试用例。
    
- **Microsoft - AI 智能体编排模式** - 在决定工作流需要直接调用模型、单个智能体还是多个智能体之前，先阅读“从合适的复杂度开始”。


# 3.在整个工作流中保留身份信息并落实数据权限

- **Microsoft - Microsoft 身份平台上的 OpenID Connect** - 从登录流程、发现端点和 ID token 校验入手，完成身份集成。
    
- **Microsoft - Azure AI Search 的安全筛选器** - 按照基于安全主体的筛选示例实践，并注意筛选器与身份认证的区别。
    
- **Microsoft - Document Intelligence 的准确率和置信度** - 在设计字段级提取检查，以及确定哪些文档结果需要人工审核时参考此文。
    
- **Presidio - 文档与示例** - 探索 PII 识别器和去标识化选项，然后针对当前配置漏检的敏感信息构建测试。

# 4. 确保集成与审批能够安全恢复

- **Temporal - 工作流执行概述** - 从持久化执行、重放和状态转换入手，理解工作流如何在中断后恢复。
    
- **MCP - 安全最佳实践** - 重点关注 token audience 校验、混淆代理风险，以及被禁止的令牌透传；这是一份仍在演进的指南草案。
    
- **Stripe - 幂等请求** - 研究一个关于幂等键与重试行为的具体 API 实现；在你集成的业务系统中验证对应契约。

# 5. 根据客户需求选择部署与推理方案

- **HashiCorp - 面向 AWS 的 Terraform 教程** - 按照教程系列，练习通过配置创建、变更和销毁基础设施。
    
- **AWS - VPC NAT 网关** - 结合你的网络图阅读，理解私有子网中的工作负载为何仍能访问外部服务。
    
- **vLLM - 快速入门** - 参考推理和在线服务示例，为模型对比中的本地方案建立起点。
    
- **vLLM - 量化** - 在选择量化 checkpoint 或规划部署规模之前，检查支持的格式和硬件兼容性。


# 6. 证明价值并移交运维责任

- **OpenTelemetry - 信号** - 从追踪、指标和日志入手，再决定各自应揭示发票工作流的哪些信息。
    
- **Google SRE Workbook - 实施 SLO** - 参考示例，为服务定义与用户相关的可靠性指标和目标。
    
- **Google SRE - 值班** - 在分配运维责任，以及帮助团队为诊断和响应故障做好准备时阅读。
