提高 AI 协同开发能力，核心不是学更多提示词，而是把 AI 纳入一个可靠的软件工程循环：**明确目标 → 给上下文 → 让它调查 → 审计划 → 小步实现 → 测试验证 → 复盘沉淀**。

**最重要的能力**

1. **把需求说成可验收的任务**

不要只说：

```
帮我优化这个页面
```

改成：

```
优化订单列表页加载体验。
目标：首屏 2 秒内出现可交互骨架屏。
约束：不改后端 API，不引入新 UI 库。
验收：npm test 通过，移动端 375px 不溢出，空状态/错误状态都有展示。
先读代码，不要马上改。
```

2. **让 AI 先读代码，再下判断**

好用的指令：

```
先不要写代码。请先找到相关文件、解释当前实现、指出改动点和风险。
```

这能显著减少 AI 凭空设计。

3. **把任务拆成小闭环**

适合 AI 的单位不是“做完整系统”，而是：

```
复现 bug → 写失败测试 → 修复 → 跑测试 → 总结影响
```

或者：

```
设计接口 → 改一个模块 → 补测试 → 验证调用方
```

4. **要求它给计划，但你负责批准计划**

常用模板：

```
请给一个实施计划，包含：
- 要改哪些文件
- 每一步的目的
- 可能破坏什么
- 如何验证
先等我确认，不要写代码。
```

5. **把 AI 当成执行力很强、但需要约束的队友**

你负责判断这些东西：

- 需求是否清楚
- 架构方向是否合理
- 边界条件是否遗漏
- 测试是否覆盖真实风险
- 改动是否过度设计

AI 负责：

- 快速读代码
- 找调用链
- 写样板代码
- 补测试
- 整理文档
- 生成替代方案
- 做初步 code review

**推荐工作流**

小改动：

```
读相关代码 → 直接改 → 跑测试 → 总结
```

中等功能：

```
需求澄清 → 设计方案 → 实施计划 → 分步改动 → 测试验证
```

复杂决策：

```
用 council 做多视角分析 → 选方案 → 用 Superpowers/Matt Pocock skills 落到 PRD/TDD/issues
```

Bug：

```
先复现，不要猜。找到最小复现路径，写失败测试，再修。
```

重构：

```
先画出当前依赖关系和风险点。保持行为不变，分阶段提交，每阶段可测试。
```

**你可以马上练的 5 个习惯**

- 每次任务都写清楚：目标、约束、验收标准。
- 默认要求 “先读代码，不要马上改”。
- 对超过 3 个文件的改动，先要计划。
- 每次让 AI 修改后，都让它说明“改了什么、怎么验证、还有什么风险”。
- 把高频流程固化成 skills 或提示模板，比如 bug 诊断、TDD、代码审查、PRD 拆 issue。

**一个高质量通用提示词**

```
你是我的协同开发伙伴。请先理解代码库，不要直接实现。

任务：
……

约束：
……

验收标准：
……

请按这个流程：
1. 找到相关文件和调用链
2. 解释当前实现
3. 给出实现计划和风险
4. 等我确认后再修改
5. 修改后运行相关测试
6. 最后总结改动、验证结果和剩余风险
```

你最近看的 `superpowers`、`council-of-high-intelligence`、`mattpocock/skills` 本质上都在做同一件事：把“随口问 AI”升级成“有流程的工程协作”。真正的提升点是：你越会定义任务、检查计划、要求验证，AI 的产出越接近可合并的工程成果。
