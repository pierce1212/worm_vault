

# HSE_B 硬件安全引擎


![](assets/2026.10.30%20信息安全硬件模块/file-20261030134801021.png)


它包含<mark style="background: #FF5582A6;">独立</mark>的 **Cortex-M 0+ 安全处理器、内部 RAM、密码运算加速器和随机数发生器**，运行 NXP 的 HSE 固件，为应用核提供安全服务。


| 硬件组成/能力      | 作用                     | 典型应用             |
| ------------ | ---------------------- | ---------------- |
| 专用安全处理器及隔离资源 | 在隔离环境中运行安全固件，处理密钥与安全服务 | 密钥管理、安全启动        |
| 对称密码硬件加速器    | 支持 AES-128/192/256 等运算 | 数据加解密、CMAC 消息认证  |
| 非对称密码硬件加速器   | 支持 RSA、椭圆曲线密码 ECC      | 固件签名验证、身份认证、密钥交换 |
| 真随机数发生器 TRNG | 提供随机熵，配合确定性随机数生成机制     | 密钥生成、认证挑战值       |
| 侧信道防护        | 提高密码运算抵抗侧信道攻击的能力       | 保护密钥等敏感资产        |


# 资源隔离与访问保护模块

这些模块也服务于功能安全，但在信息安全中可用于限制软件或总线主设备访问敏感资源。

|模块|主要作用|如何理解|
|---|---|---|
|**XRDC**：扩展资源域控制器|按域控制 CPU、DMA 等主设备对存储器及外设的访问|控制“哪个主设备能访问哪些资源”|
|**Cortex-M7 MPU**：内存保护单元|对本核访问设置读、写、执行权限及特权限制|控制“本核软件能读、写、执行哪些地址”|
|**VIRT_WRAPPER**：引脚隔离模块|配合 XRDC 实现 GPIO 引脚级隔离|限制不同域对引脚的控制|
|**REG_PROT**：寄存器保护模块|对指定关键寄存器或位域实施写保护、锁定|防止关键配置被非法修改|


# 生命周期、调试保护及安全配置存储

这一类是多个<mark style="background: #FF5582A6;">硬件与固件机制协同实现的</mark>，不能全部看成独立外设：

- **生命周期管理 LC**：根据芯片所处制造、交付、使用阶段，逐步限制安全资源访问；生命周期推进具有不可逆性。[NXP 生命周期说明](https://community.nxp.com/t5/S32K/lifecycle-transition-in-s32k3/td-p/1812713)
- <mark style="background: #FF5582A6;">**安全调试保护**：控制调试接口访问，涉及 ADKP（应用调试密钥/口令）及相关安全策略。</mark>（不了解）
- <mark style="background: #FF5582A6;">**UTEST 中的 OTP 安全属性**</mark>：保存特定一次性配置，例如 ADKP；它与普通可更新的密钥存储不同



# MU： 应用核调用 HSE 的通信接口

![](assets/2026.10.30%20信息安全硬件模块/file-20261030140405375.png)


MU（Messaging Unit，消息单元）<mark style="background: #FF5582A6;">负责应用 Cortex-M 7 与 HSE 之间的请求、响应和状态通知</mark>。它本身不做加解密，软件通常通过以下路径调用安全服务：

`应用 / Bootloader → HSE 驱动 → MU → HSE_B → 返回结果`

例如，Bootloader 请求 HSE 校验固件签名，再根据结果决定是否启动应用。
