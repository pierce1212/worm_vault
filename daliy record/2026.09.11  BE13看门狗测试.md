# 看门狗实现

![](assets/2026.09.11%20%20BE13看门狗测试/file-20260911151551171.png)

BE 13/900719 使用通过 SPI 服务的问答式看门狗。MCU 必须在允许的时间内交出按规定算法计算的 16 位答案。

| 地址   | 寄存器              | 作用                          |
| ---- | ---------------- | --------------------------- |
| 0x20 | WDCFG            | 看门狗配置和状态                    |
| 0x21 | WDSEED           | MCU 写入的 16 位种子；写 0xFFFF 被忽略 |
| 0x22 | WDMR             | MCU 算出的答案；写入触发一次服务和比较       |
| 0x23 | WDAR             | BE13 算出的答案，MCU 可读回进行反向检查    |
| 0x35 | INT1.WDFLT       | 看门狗超时故障标志                   |
| 0x3A | SVFLT.ALU_OVRFLW | 运算不匹配计数达到复位阈值的标志            |
默认超时典型值 512 ms，规格范围 408～616 ms

| 寄存器           | 判断内容                    | 正常期望           |
| ------------- | ----------------------- | -------------- |
| `WDCFG`（0x20） | `WD_ER_CNT[2:0]` 问答错误计数 | 保持为 0          |
| `WDAR`（0x23）  | BE13 自己计算出的答案           | 等于对应轮次写入的 WDMR |
| `INT1`（0x35）  | `WDFLT` 超时故障            | 0              |
| `SVFLT`（0x3A） | `ALU_OVRFLW` 答案错误累计故障   | 0              |
这里的喂狗就是通过 WDMR MCU 算出的答案；写入触发一次服务和比较。
MCU 读取 BE 13 的 WDAR，但是没有进行比较。
`WD_ER_CNT` 增加到 5 时，BE 13 就会拉低 `RSTB`，触发 MCU 复位，并置位 `ALU_OVRFLW`。

```

- MR 与 AR 不匹配：错误计数 **加 1**。
- MR 与 AR 匹配：错误计数 **减 1**，最低为 0。
- 错误计数达到 **5**：产生复位。
**累计计数达到 5**，并非必须连续错误 5 次；中间一次正确只减 1
```

<mark style="background: #FF5582A6;">注：**停止喂狗导致的超时会直接触发复位，不需要等错误计数达到 5**。</mark>

## 验证 RC 影响

**有可能影响，但目前不能认定 C 227 导致 WDFLT 变成 0。**

图中 **R 227＝10 kΩ，C 227＝100 nF**，时间常数为：

```
τ = R × C = 1 ms
```

当 BE 13 拉低 RSTB 时，电容放电；BE 13 释放输出后，电容通过 R 227 充电，**RSTB 会缓慢上升，而不是立即回到高电平**。R 301 断开并没有移除这组 RC，所以这种影响仍在。


![](assets/2026.09.11%20%20BE13看门狗测试/file-20260915152359919.png)

去除 电容后，可以正常读取了，稳定的 1，而不是 0 了。

最符合手册和现象的解释是：

1. 看门狗超时，BE 13 置 `WDFLT=1`，内部下拉管把 RSTB 拉低，C 227 也随之放电。
2. 约 45 ms 后，BE 13 关闭下拉管，准备释放 RSTB。
3. **C 227 的电压不能立即升高**，需要通过 R 227 充电，因此引脚还会维持一段低电平。
4. BE 13 可能把“自身已释放、引脚却仍为低”的情况识别为**外部复位**，于是清除原故障标志，只留下 `EXT_RST`。

在 MCU 已隔离、仅考虑这支 RC 时：

```
R227 × C227 = 10 kΩ × 100 nF = 1 ms
```

理想情况下，从 0 V 充到 0.8 V 也需要约 **174 µs**。而手册给出的外部复位检测时间是微秒量级，所以这个延迟不能忽略。

**去掉 C 227 后，RSTB 释放得更快，WDFLT 得以保持为 1**，与你的测试结果一致。具体内部判定时刻还没有直接测到，但现在已有硬件对照支撑这个解释。

![](assets/2026.09.11%20%20BE13看门狗测试/file-20260915153959111.png)
![](assets/2026.09.11%20%20BE13看门狗测试/file-20260915154013338.png)

- **看门狗超时**：BE 13 设置 `WDFLT=1`，主动拉低 RSTB，电容放电。
- **BE 13 结束复位输出**：内部下拉关闭，但 C 227 需要充电，引脚不能立即升高。
- **释放后的低电平被识别为外部复位**：这会清除 `WDFLT`，留下 `EXT_RST`，所以读到 **0**。
- **MCU 仍然不喂狗**：BE 13 的看门狗重新计时，再次超时，又设置 `WDFLT=1`。

![](assets/2026.09.11%20%20BE13看门狗测试/file-20260915155808028.png)

**你看到的反复 0/1，可以解释为：看门狗不断把故障位置 1，而复位释放过程又触发了另一种清除条件，把它清成 0。不是读取动作在清零。**

其中，**C 227 确实影响了故障标志的保持**，这是你拆除前后的对照证明的；“释放沿触发外部复位判定”是目前最符合手册和实验的机制解释，但手册没有完整公开内部检测时序，不能把这部分说成已直接测实。

先把几个时间分清：

|参数|含义|
|---|---|
| `tWATCHDOG`，默认典型 512 ms|两次服务之间允许的看门狗超时；你从停喂标记测到约 490 ms，与它相符|
| `tRSTB_REC`，典型 45 ms|看门狗故障后，RSTB 保持低电平的时间；手册第 23 页|
| `tRSTB_OFF`，最大 22 µs|图 6 中**下电时**，RSTB 拉低与后续电源下降之间的时序延迟|
| `R227×C227＝1 ms` |板上复位线的 RC 时间常数，描述释放后的充电速度|

**22 µs 不是“RSTB 必须在此时间内拉高”，也不是整个看门狗复位动作的完成期限。**

整个过程可以这样理解。

**① 停止喂狗，BE 13 计时到期。**

按手册 6.21.3，超时后 BE 13：

- 将 `INT1.WDFLT` 置为 **1**；
- 拉低 RSTB，使连接的 MCU 复位。

错误答案测试则由错误计数达到 5 触发，设置的是 `SVFLT.ALU_OVRFLW`。

**② BE 13 保持 RSTB 为低电平。**

这段时间典型约 **45 ms**。BE 13 的下拉电路导通，C 227 被放电。

手册第 24 页表 16 的注释 23 明确说明：**看门狗故障造成的内部复位，会复位相关配置，但保留故障标志。** 因而，单纯这次看门狗复位，不应该直接把 WDFLT 清掉。

**③ 45 ms 结束，BE 13“释放引脚”。**

这里容易混淆：

> BE 13 释放 RSTB，并不等于引脚电压已经立即变高。

内部下拉关闭后，由 R 227 给 C 227 充电，电压逐渐上升。在 MCU 隔离、忽略其他负载、按 0 V 向 5 V 充电的理想模型估算：

```
时间常数：10 kΩ × 100 nF = 1 ms
达到 0.8 V：约 174 µs
达到 2.0 V：约 511 µs
```

所以，BE 13 已经不再主动拉低时，**线路仍可能在一段时间内被识别为低电平**。

**④ 我们推断：这段低电平又被识别成了“外部复位”。**

手册第 23 页说明，RSTB 同时具有复位输入功能，外部复位检测是微秒量级。

第 24 页表 16 的注释 28 则说明：**外部复位会让寄存器恢复初值，`EXT_RST` 例外。**

如果步骤③的释放拖尾触发了这个判定，就会得到：

```
WDFLT：1 → 0
EXT_RST：置为 1
```

这里不是“电容直接修改寄存器”，而是：

```
电容拖慢电压上升
    → 影响复位输入判定
    → 芯片执行外部复位处理
    → 故障标志被清除
```

**⑤ MCU 仍然不喂狗，于是下一轮又开始。**

在你隔离 R 301 的试验中，MCU 没有重启，测试变量一直是 1。BE 13 看门狗重新开始计时，下一次超时又把 WDFLT 置 1。

于是可能形成：

```
持续停喂
  → 超时，WDFLT=1
  → RSTB 拉低约45 ms
  → 释放后出现电容拖尾
  → 若被判为外部复位，WDFLT=0
  → 重新计时
  → 再次超时，WDFLT=1……
```

这就解释了为什么 **MCU 不复位时能观察到跳变，而 MCU 随之复位时，启动后可能只读到 0**：MCU 能重新执行 SPI 读取时，那个短暂的 `WDFLT=1` 阶段可能已经过去。

去掉 C 227 后，释放沿加快；你的实验中 WDFLT 不再被清掉，即使看门狗继续超时，读到的仍可一直是 1。**这与“读取不清除，释放过程影响标志保持”的解释一致。**

但最后这一点仍需明确：**你已经验证了 C 227 与现象的关联；尚未直接测实 BE 13 内部是在什么时刻、按什么检测窗口，将该释放过程判成外部复位。** 因此不能用“1 ms 超过 22 µs”作为根因结论。

|参数|手册数值|含义|
|---|---|---|
|输入低电平边界|**0.8 V**|外部拉低时，应降至低电平有效范围|
|输入高电平边界|**2.0 V**|释放后，应升至高电平有效范围|
|输入门限迟滞|最小 **100 mV**|上升、下降的实际翻转门限存在差别|

|参数|最小|典型|最大|
|---|---|---|---|
|外部复位检测时间 `tRSTB_EXE`|1 µs|—|4 µs|
|MCU 外部复位最小持续时间 `t_RST_MIN`|8 µs|10 µs|—|

- **1～4 µs 是外部复位检测时间，不是下降沿时间要求。**

- **36～54 ms 对应 BE 13 看门狗故障等情况下输出的复位低脉冲。** 你测得约 40 ms，符合这一项。
