# 哈希、加密、数字签名


|技术|主要解决什么问题|例子|
|---|---|---|
|加密|防止别人读懂内容|AES、SM4、RSA|
|哈希|给数据计算一个固定长度的“指纹”，通常不能逆向还原|SHA-256、SM3|
|数字签名|验证数据来源，并发现数据被修改|RSA 签名、ECDSA、SM2 签名|

- **哈希不是加密。**它没有对应的“解密”操作；单独使用哈希也不能防止攻击者同时替换数据和哈希值。
- **签名不负责保密。**它通常是“私钥签名、公钥验证”，不能简单理解成“私钥加密”。

密钥模式：
使用 AES 算法加密时，可以使用不同的加密模式。AES 加密模式包括：ECB（电码本模式）、CBC（密码分组链接模式）、CFB（密码反馈模式）、OFB（输出反馈模式）、CTR（计算器模式）。
其中，工程上常使用 <mark style="background: #ADCCFFA6;">ECB 和 CBC 模式</mark>，<mark style="background: #FF5582A6;">ECB 模式只需要输入密钥即可，而 CBC 模式，除了输入密钥以外，还需要输入密钥初始值</mark>。

填充模式：
由于 AES 算法采用对称分组密码体制，因此，在 AES 进行数据加密前，需要将明文拆分成固定长度块（16 byte）。如果输入的明文数据长度不是 16 byte 怎么办呢？**答**：进行填充处理，以此确保每组数据块的长度为 16 byte。

如果填充方式选择 None，则明文和密文长度相等；如果填充模式使用非 None 模式，明文和密文的长度不同。

## 签名
使用私钥对信息处理的过程。
![](assets/2026.11.13%20boot+信息安全%20-%20SHA-256%20AEC-CMAC%20AES%20128-CMAC/file-20261113171845487.png)

工程上，常常先通过哈希算法（eg：SHA 256）对目标数据进行计算，得到一个固定长度的哈希值（eg：32 byte），这个哈希值也可称为摘要信息。之后，使用私钥对摘要信息进行加密处理，得到密文，这个过程就称为签名（Sign）。上位机或者云端将原始数据和密文发送给目标控制器，目标控制器使用配对公钥对密文解密得到摘要信息（明文 1），同时，控制器对接收到的原始数据进行同样的哈希计算，得到明文 2，如果 明文 1 == 明文 2，则验签通过，反之，失败。

签名（Sign）和验签（Verify）成对出现，使用非对称算法时，一般常见的用法：签名方使用私钥签名，接收方使用对应的公钥验签。


# 什么是 CMAC

AES-CMAC 是基于 AES 加密算法的一种消息认证码算法，主要用于确保数据的完整性和真实性。
**CMAC 通常指基于分组密码的消息认证码**（Cipher-based Message Authentication Code），常见形式是 **AES-CMAC**。


它用一把共享密钥，对一段数据计算出一个“认证标签”。接收方用相同密钥重新计算并比较，以判断：

- **数据是否被篡改**。
- **发送方是否持有正确密钥**。

发送方：密钥 + 报文数据 → CMAC 标签 → 发送报文和标签
接收方：用相同密钥重新计算 → 比较标签 → 判断是否通过认证

<mark style="background: #BBFABBA6;">**CMAC 不加密原始数据**，报文内容仍然可见；它也不能单独防止重放攻击，通常需要将计数器或新鲜度值一起纳入计算。AUTOSAR SecOC 中就可能使用 AES-CMAC。</mark>



> [!NOTE] Title
> CMAC 基于 CBC-MAC 的链式计算结构，但不要求待认证的数据必须用 CBC 模式加密。
> 
> 
> - **CBC 加密**：将明文变成密文，用于保密。
> - **CMAC 认证**：用分组密码（例如 AES）计算认证标签，用于检查完整性和真实性。
