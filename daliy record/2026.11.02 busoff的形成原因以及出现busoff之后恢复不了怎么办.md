# 现象



当被测试的 CAN 节点的 busoff 故障之后，被测试 CAN 节点无法恢复正常通信，即 busoff 的快慢恢复机制和慢恢复机制没有起作用。

为什么 busoff 的恢复机制没有起作用呢？是什么因素干扰了 busoff 恢复？


> [!NOTE] 什么是 busoff
> 当前节点的 controller 关闭，节点无法在其期间收发报文。（注意!!！此期间 ECU 依然正常运行，所有的任务依然被 OS 调度，如果节点一直收不到网络管理报文，网络切换到 bus sleep mode ,则 ECU 会进入下电流程。





# busoff 的直接原因

TEC >= 255

> [!NOTE] TEC
> TEC 的计数实质是一个硬件计数，每个 CAN 模块会有一个专门的寄存器存储 TEC

# busoff 恢复的原因

![](assets/2026.11.02%20busoff的形成原因以及出现busoff之后恢复不了怎么办/file-20261102091947389.png)

让 CC 从 busoff 恢复到 Error active 条件：
有模式请求动作，具体说就是操作 CC 对应的寄存器
经过 128 次连续的 11 个隐性位。



> [!NOTE] error passive 的原因
> 可以通过 读取错误计数寄存器的位


> [!NOTE] 恢复时间
> 就是 CC 从 busoff 模式切换到 Error Active 的用时。


# TEC 的累加规则


1. 发送节点在发送时，产生错误标志，TEC + 8.

![](assets/2026.11.02%20busoff的形成原因以及出现busoff之后恢复不了怎么办/file-20261102094356439.png)

2. 发送节点在发送主动错误标志或者过载标志时，检测出位错误 TEC + 8
3. 节点从主动错误标志，过载标志的最开始检测出连续 14 个显性位之后，每检测出连续 8 个显性位，TEC + 8
4. 被动错误标志后检测出连续 8 个显性位。TEC+8
5. 发送节点正常发送完一帧数据，且被其他接收节点应答（ACK）. TEC - 1.如果 TEC 是 0，则保持 0
6. 如果节点已经 busoff，当检测到 128 个连续 11 个 bit 隐性位时，TEC = 0;
7. 

# 如何理解 busoff 为什么要等待 128 次连续 11 个隐性位？（11898 的规范）

![](assets/2026.11.02%20busoff的形成原因以及出现busoff之后恢复不了怎么办/file-20261102092728729.png)

帧间隔（3 个隐性位） + 应答界定符(ACK field 1 个隐性位)  + EOF (7 个隐性位)  

节点在请求 CAN bus 使用权之前，需要先监听总线的状态，只有总线处于空闲状态的时候，发送节点才能发送起始位（SOF），之后，请求发送报文的各个节点进行仲裁。
如何识别 CAN 总线空闲呢？ 监听到总线 >= 11 bits 隐性位。也就是说 CAN BUS 又忙碌进入空闲，最快 11 bits 时间，这里的 11 bits 对应的 time = 1/500 kbps = 2 us，CANBUS 由忙碌进入空闲最快 11 * 2 us = 22 us*

# 为什么 CAN 总线的负载率不要超过 30%

CAN 总线负载率：= （单位时间内传输的 bit 个数）/ (单位时间内可以传输的 bit 个数)


> [!NOTE] 有效负载率
> 有近乎一半的 bit 在传输协议信息，所以总线的有效负载率很低 ，差不多时计算出来的一半。

所以可以思考：总线的负载率提高，意味着总线上发送的报文数量多，发送的报文数量多，就会导致低优先级的报文获取总线使用权的机会降低，进而导致通信问题。


# CANSM 对 busoff 的处理

发生 busoff 以后，驱动层会将 busoff 状态信息传递给上层，以便于模式管理。CANSM 的状态变化主要是:
CANSM_BSM_S_SILENTCOM_BOR    CANSM_BSM_S_SILENTCOM 如下所示


![](assets/2026.11.02%20busoff的形成原因以及出现busoff之后恢复不了怎么办/file-20261102102527850.png)


当 busoff 发生以后，如果 CC 状态切换次数超过了 T_REPEAT_MAX 阈值，且没有通信模式请求，CANSM 模式会进入 CANSM_BSM_S_PRE_NOCOM 模式，最终进入 CANSM_BSM_S_NOCOM 模式。在 CANSM_BSM_S_NOCOM 模式下，CANSM 会将 CAN transceiver 和 CAN CC 设置对应的低功耗模式，或者说不工作的模式。
