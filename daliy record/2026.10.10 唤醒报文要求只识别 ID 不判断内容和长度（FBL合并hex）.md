## 什么是任意帧唤醒

CAN standard wake-up，标准唤醒模式，只要满足硬件的唤醒时序即可完成收发器的唤醒，也可以理解为“任意帧唤醒”，唤醒时序如下所示：
![](assets/2026.10.10%20唤醒报文要求只识别%20ID%20不判断内容和长度（FBL合并hex）/file-20261012112444415.png)

不筛选特定 ID、数据，符合硬件条件的总线活动即可触发

<mark style="background: #FF5582A6;">**“任意”不代表任意电平毛刺都能唤醒。** 收发器通常要检测符合时序和滤波条件的唤醒模式（WUP），具体看芯片手册。</mark>

CAN 收发器处于 Offline 模式，并满足：

- `CWE = 1`：允许 CAN 唤醒。
- `CPNC = 0` **或** `PNCOK = 0`：选择性唤醒关闭，或 PN 配置无效。

显性（逻辑 0） → 隐性（逻辑 1） → 显性（逻辑 0）
≥ t_wake(busdom)  ≥ t_wake(busrec)  ≥ t_wake(busdom)

理解“任意帧”时，关键是：**不限 ID，但必须满足上述电平时序；硬件并不以完整接收一帧且 CRC 正确作为标准唤醒条件。**


## 什么是特定帧唤醒

WUF（Wake-up frame），也就是特定的唤醒帧（eg：特定范围的 CanNM 报文），这种类型的唤醒需要在 uC 下电流程中，通过 SPI 设置 TJA 1145 的 ID 等寄存器。
**特定帧唤醒，就是 ECU 休眠时，由 CAN 收发器识别符合预设条件的报文，再触发 ECU 唤醒。** 在 TJA 1145 中叫**选择性唤醒（Selective Wake-up）**，符合条件的报文叫 **WUF（Wake-Up Frame，唤醒帧）**。

TJA 1145 支持两种筛选方式：

- ** `PNDM = 0` **：按配置的帧格式、ID 和 ID 掩码筛选，不比较 DLC 和数据，但仍检查 CRC。
- ** `PNDM = 1` **：进一步要求 DLC 匹配；数据长度大于 0 时，收到的数据与数据掩码至少有一个对应位同时为 1。数据筛选不是整个字节完全相等。

##  FULL CAN 和 basic CAN 


- **BasicCAN**：一个 HWObject(Hardware Object)可以处理一段范围的 CanId
    
- **FullCAN**：一个 HWObject(Hardware Object)只能处理单个 CanId
