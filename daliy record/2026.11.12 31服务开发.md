DcmDspRoutine_0 x 203
└─ DcmDspStartRoutine_0 x 203      ← 启动子服务 0 x 01
   ├─ CommonAuthorizationRef   ← 调用权限
   ├─ StartRoutineIn           ← 请求输入，当前没有配置
   └─ StartRoutineOut
      └─ Signal_0 x 203          ← <mark style="background: #FF5582A6;">返回一个状态字节</mark>


请求：31 01 02 03
         │  │ └─── RID
         │  └───── 启动
         └──────── 例程控制

响应：71 01 02 03 XX
                  └─ Signal_0 x 203，配置的 1 字节输出

此外，DcmDspRoutineUsePort = true 表示通过 **RTE 接口**调用应用函数。生成代码把启动子服务连接到；
Rte_Call_RoutineServices_DcmDspRoutine _0 x 203_ Start(...)
再由 RTE 调用应用里的：
RoutineServices_DcmDspRoutine_Routine_Control _203_ Start(...)

###  4.2.3 (c) Programming Condition Check/编程条件检查 ($<mark style="background: #FF5582A6;">31 01 0203</mark>)：

| 核心需求                                       | 当前代码情况                                             | 判断                         |
| ------------------------------------------ | -------------------------------------------------- | -------------------------- |
| 支持 `31 01 02 03`，返回 `71 01 02 03 SS`       | DCM 配置、RTE 连接和应用回调均已有，输出一个状态字节                     | **已实现**                    |
| 电压必须满足 `9V < V < 16V`，否则返回 `02`            | 已检查电压，但代码允许 **9V、16V** 通过                          | **部分实现：边界错误**              |
| 有效车速必须 `< 5km/h`，否则返回 `03`                 | 已检查车速，但代码允许 **5km/h** 通过                           | **部分实现：边界错误**              |
| 车速缺失或无效时，该项放行，其他条件继续检查                     | `Com_ReceiveSignal` 返回非 `E_OK` 时会放行；没有完整判断信号超时、无效值 | **部分实现**                   |
| 所有条件独立评估，全部满足才通过                           | 电压异常后，通过 `else if` 跳过车速条件评估，实际为“电压优先”              | **未按独立评估实现**               |
| 档位须为 P/N，可选；不得限制发动机转速                      | 没有档位检查，也没有发动机转速限制                                  | **转速要求满足；档位是否需要实现取决于项目选择** |
| 条件不满足时，不允许进入 Boot                          | 检查结果只写入响应；会话切换权限回调直接返回 `E_OK`，跳 Boot 回调也未检查这个结果    | **未实现检查结果与进入 Boot 的联动限制**  |
| StayInBoot 或 APP 标志无效进入 Boot 时，检查固定返回 `00` | 已查看的配套 Boot 源码仍执行电压检查，没有针对这两种场景的放行分支               | **配套源码中未实现**               |

    ↓
