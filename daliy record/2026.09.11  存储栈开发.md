## 存储流程

```
NvM             管理需要保存的数据块
 ↓
MemIf           提供统一接口
 ↓
Fee             用 Flash 模拟 EEPROM
 ↓
MemAcc          管理地址和访问请求
 ↓
Mem_43_INFLS    驱动内部 Flash 硬件
 ↓
Data Flash
```

#### 不清楚 ROM block 和 NM block 的区别

| 存储块           | 保存的内容       | 此时的值  |                                                      |
| ------------- | ----------- | ----- | ---------------------------------------------------- |
| **ROM Block** | 软件预设的出厂默认音量 | **5** |                                                      |
| **NV Block**  | 用户最后保存的音量   | **8** | 只有再 NvM_WriteBlock 或者 writeall 这样的函数，才会往 NVblock 里面写 |
|               |             |       |                                                      |

ROM Block 是“默认答案”，NV Block 是“上次保存的答案”。必须区分它们，才能既记住你的修改，又保留恢复默认值的依据。
ROM Block → 软件预先定义的默认高度数据
NV Block  → 车辆运行后，实际保存下来的高度数据


#### 如何选择 ROM block 或者 NV block

<mark style="background: #FF5582A6;">不用由应用代码在 ROM 和 NV 之间选择。你正常读取 RAM Block，启动时 NvM 会按配置决定用什么数据填充它。</mark>

启动时 NvM_ReadAll()
        │
        ├─ NV 中保存的数据有效
        │       → 把 NV 数据读入 RAM Block
        │
        └─ NV 数据无效，且配置了 ROM 默认值恢复
                → 把 ROM 默认值复制到 RAM Block

应用通过 Rte_Read() 读取 RAM Block

#### SWC 这里的 NVBLOCK 配置是如何跟 BSW NVM 的配置产生联系的呢？


**SWC 的 NvBlock 与 BSW 的 NvM，通过 RTE 配置中的 `RteNvRamAllocation` 建立联系。** 其中有两个引用：一个指向 SWC 的 descriptor，另一个指向 BSW 的 descriptor，并不是只靠名字相似来匹配。


1. SWC 层：描述“应用要保存什么数据”

NvBlock
└─ NvBlockDescriptor_DIDF 18 C
   ├─ NvBlockDataMapping
   ├─ NvBlockNeeds_DIDF 18 C
   ├─ DIDF 18 CRamBlock
   └─ DIDF 18 CRomBlock

|SWC 配置|作用|
|---|---|
|`NvBlockDataMapping`|把端口上的数据元素映射到 RAM Block|
|`RamBlock`|定义运行时缓冲区的数据类型|
|`RomBlock / Init Value`|定义默认值|
|`NvBlockNeeds`|描述启动恢复、下电保存、立即保存、CRC 等需求|
RTE 层：明确指定“这个 SWC 块对应哪个 NvM 块”

![](assets/2026.09.11%20%20存储栈开发/file-20261014165200220.png)


BSW 层：描述“NvM 如何管理和保存这份数据”
BSW 的 `NvBlock_NvBlockDescriptor_DIDF18C` 配置了 RAM、ROM 地址：

NvMRamBlockDataAddress =
Rte_RamBlk_NvBlock_NvBlockDescriptor_DIDF 18 C_DIDF 18 CRamBlock

NvMRomBlockDataAddress =
Rte_RomBlk_NvBlock_NvBlockDescriptor_DIDF 18 C_DIDF 18 CRomBlock
