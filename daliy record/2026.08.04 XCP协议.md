### 核心结论

SC 900719 内部集成了两路相互独立的高速 CAN 物理层接口。两路都能正常收发，但低功耗和唤醒能力不同：

|特性|CAN 1|CAN 2|
|---|---|---|
|正常模式收发|支持|支持|
|最高常规波特率|1 Mbps|1 Mbps|
|面向 2 Mbps 的动态特性|有|有|
|独立 5 V 供电 `VCCx_CAN` | `VCC1_CAN` | `VCC2_CAN` |
|低功耗状态|监听唤醒，输入电阻接地|CANH/CANL 高阻悬空|
|总线唤醒|部分料号支持|不支持|

<mark style="background: #FF5582A6;">注意：文档只是为最高 2 Mbps 给出了额外动态特性，不能直接理解为完整支持 CAN FD。</mark>

### 工作模式

通过 SPI 的 `CANx_MODE` 位控制：

- `CANx_MODE = 1`：正常模式，也是默认值；允许 MCU 与总线双向通信。
- `CANx_MODE = 0`：低功耗模式；普通报文无法发送或接收。
- 正常模式下，总线共模偏置约为 `VCCx_CAN / 2`。
- 供电启动期间保持隐性状态，不产生异常显性脉冲。
- `RXDx` 的数字输出电平由 `DOSV` 决定，可为 3.3 V 或 5 V。

CAN 1 的可选唤醒采用三段式模式识别：

`显性 → 隐性 → 显性`

三个事件必须通过时间滤波，并在 `tWUTO` 窗口内完成；识别成功后唤醒事件被锁存。

### 故障保护

- TXD 永久显性：
    
    当 `TXDx` 保持显性超过 `tX_DOM`，芯片关闭对应 CAN 发送驱动，并置位 `CANx_TXD_PD`。接收器仍继续工作，避免一个故障节点长期拉死整条总线。
    
- 过温：
    
    达到 `TOTRISE_CANX` 后关闭 CANH/CANL 发送驱动，并置位 `CANx_OT`；接收器仍工作。温度降至 `TOTFALL_CANX` 以下后，在下一次 TXD 隐性到显性跳变时自动恢复发送。
    
- 总线短路：
    
    CANH/CANL 集成限流，防止对地或对电源短路造成过大电流。短路保护与过温关闭机制配合工作。
    
- 感性短路耐受：
    
    文档给出的测试条件包括约 20 m 线束、20 µH 附加电感、+40 V 和 −27 V，合格标准是器件不损坏。这是耐受试验，不代表这些电压属于正常工作范围。
    

### 关键电气参数

- 功能供电范围：`5.5–20 V`
- 常规工作能力：最高 `1 Mbps`
- TXD→RXD 环路延迟：最大 `255 ns`
- TXD→总线、总线→RXD 延迟：`37.5–150 ns`，典型 `75 ns`
- CANH/CANL 上升、下降时间：最大 `50 ns`
- TXD 永久显性超时：`2.5–16 ms`
- 显性差分电压：`1.5–3.0 V`，典型 `2.0 V`
- 隐性差分电压：`−500–50 mV`
- 接收共模范围：`−12–12 V`
- 发送过温关闭阈值：典型 `210°C`
- 过温恢复阈值：典型 `195°C`

### 对当前工程的意义

- 普通通信：MCU `FLEXCAN_1` → SC 900719 CAN 1
- XCP：MCU `FLEXCAN_2` → SC 900719 CAN 2
 CAN 2 不能唤醒 ECU；
- 进入低功耗后，CAN 2 _H/CAN 2_ L 会变为高阻，CANape 无法连接；
- 应检查 SPI 中的 `CAN2_MODE`；
- 若能接收到 `0x332`，却始终发不出 `0x333`，要检查 `CAN2_TXD_PD` 和 `CAN2_OT`；
- 当前工程中 XCP 网络的 CanTrcv 句柄为 `255`，所以很可能需要 SBC/SPI 驱动单独管理 CAN 2，而不是由 AUTOSAR CanTrcv 管理。

## 从一帧 CONNECT 看懂 XCP


![](assets/2026.08.04%20XCP协议/file-20260806150642874.png)
### CTO 和 DTO

XCP 报文主要分为两类。
### CTO：Command Transfer Object

用于命令控制，典型用途：

```
CANape → ECU：CONNECT
ECU → CANape：CONNECT响应
CANape → ECU：UPLOAD
ECU → CANape：数据响应
```
CTO 包括：
- 命令包；
- 响应包；
- 错误包；
- Event/Service 请求。

### DTO：Data Transfer Object

用于数据传输，最典型的是 DAQ：

```
ECU按照10 ms事件周期
  ↓
读取配置好的变量
  ↓
打包成DTO
  ↓
主动发送给CANape
```

当前工程的 A 2 L 中：

```
CAN_ID_MASTER = 0x332
CAN_ID_SLAVE  = 0x333
```

通常：

- `0x332` 上的命令属于 CTO；
- `0x333` 上的响应属于 CTO；
- `0x333` 上的 DAQ 测量数据属于 DTO。
