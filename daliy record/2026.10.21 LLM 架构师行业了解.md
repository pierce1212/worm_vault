# 我想要干什么？
我是只想应用开发，还是说我想研究大语言模型技术？我需要区分这三个问题：
模型为什么会回答、怎样训练得更好、怎样让它可靠地完成实际任务。


第一层：模型本身——它为什么能理解和生成语言？

|技术点|通俗解释|值得研究的问题|
|---|---|---|
|Token与分词|把文字拆成模型处理的基本单位|为什么同一段话用不同模型，Token数不同？|
|Embedding，向量表示|用一组数字表示文字及其特征|模型怎样表示词义和语义关系？|
|Transformer与注意力机制|根据上下文计算各部分信息的关联|模型怎样利用前文理解一句话？|
|自回归生成与采样|逐步预测下一个Token，再接着生成|为什么同一个问题能给出不同答案？为什么会胡编？|

第二层：训练与推理——怎样让模型更强、更省？

|技术点|通俗解释|值得研究的问题|
|---|---|---|
|预训练与数据工程|从大量数据中学习规律|数据质量、重复数据、数据配比怎样影响能力？|
|监督微调，SFT|用任务示范继续训练模型|怎样让模型更会遵循指令、适应某类任务？|
|LoRA等高效微调|只训练较少的附加参数|怎样降低微调所需的算力和显存？|
|偏好优化与强化学习|用偏好或奖励信号调整行为|怎样让回答更符合要求？怎样避免奖励设计出错？|
|推理优化|优化模型实际运行的过程|怎样减少显存、降低延迟、提高并发？|

第三层：应用系统——怎样让模型真正完成工作？

|技术点|通俗解释|值得研究的问题|
|---|---|---|
|Prompt与结构化输出|明确任务、规则和输出格式|怎样稳定输出可供程序处理的结果？|
|RAG，检索增强生成|先查外部资料，再结合资料回答|怎样检索到正确材料，并让答案有依据？|
|上下文与记忆管理|选择、保存和取回任务需要的信息|对话越来越长时，哪些该保留、压缩或重新检索？|
|工具调用与Agent|让模型通过程序查询数据、执行操作|如何选工具、处理失败、判断任务完成？|
|多Agent协作|让多个模型实例分工|什么时候分工有效，什么时候只增加成本？|
|评估、监控与安全|衡量效果并约束执行行为|怎样发现错误、阻止越权、复现失败？|

# 招聘内容


公司正在构建一款面向日常用户的主动式 AI 智能助手，旨在为对话、日常事务、组织安排和工作流程带来智能化体验。
我们的产品专注于为长时间运行的工作流、持久化的上下文以及真实世界中的任务完成提供高可靠性。系统必须能够处理多步推理、与外部工具交互，并在模型行为存在非确定性的情况下保持可靠。
职位描述
你将负责将研究方向转化为可投入生产的、工业级的机器学习系统。该职位主导 A1 智能能力的执行层——包括训练管道、推理系统、评估工具以及部署。

核心职责
构建并主导端到端的 ML 管道，涵盖数据、训练、评估、推理和部署
使用先进的方法（如 LoRA、QLoRA、SFT、DPO、蒸馏等）对模型进行微调和适配
设计并运营可扩展的推理系统，在延迟、成本和可靠性之间取得平衡
设计并维护数据系统，以支持高质量的合成数据与真实训练数据
与研究负责人合作，落地覆盖性能、鲁棒性、安全性与偏见的评估管道
主导生产环境的部署，包括 GPU 优化、内存效率、延迟降低及扩缩容策略
与应用工程团队紧密协作，将 ML 系统干净地集成到后端、移动端和桌面端产品中
做出务实的技术权衡，快速交付改进，从真实使用中学习
在真实的产线约束下工作：延迟、成本、可靠性和安全性

职位要求
扎实的深度学习背景，熟悉基于 Transformer 的架构
具备在生产环境中训练、微调或部署大规模 ML 模型的实践经验
熟练使用至少一种现代 ML 框架（如 PyTorch、JAX），并能快速学习其他框架
熟悉分布式训练与推理框架（如 DeepSpeed、FSDP、Megatron、ZeRO、Ray）
扎实的软件工程基础——能够编写健壮、可维护、生产级别的系统
具备 GPU 优化经验，包括内存效率、量化和混合精度
能够独立主导模糊、从 0 到 1 的 ML 系统
倾向于快速交付、快速学习，并通过迭代改进系统

加分项（理想经验）
有 LLM 推理框架经验，如 vLLM、TensorRT-LLM 或 FasterTransformer
为开源 ML 或系统库做过贡献
有科学计算、编译器或 GPU 内核相关背景
有 RLHF 管道经验（PPO、DPO、ORPO）
有训练或部署多模态模型或扩散模型的经验
有大规模数据处理经验（Apache Arrow、Spark、Ray）

# 总结



<mark style="background: #FF5582A6;">把底层能力做深，再向机器人控制系统和学习算法部署延伸。
偏上层 Agent 和 ML 系统，会让人低估底层工程的价值。
你的成长关键，是逐步承担更完整的系统问题，而不是只完成协议收发。
</mark>

|能力方向|建议投入|学习重点|
|---|---|---|
|**关节通信与实时系统**|当前主线|按产品选CAN/CAN FD或EtherCAT；时序、同步、总线负载、故障恢复、RTOS或实时Linux|
|**关节控制基础**|优先补齐|电流／速度／位置环的关系，力矩与电流关系，编码器、标定、限位；理解阻抗控制|
|**整机软件接口**|下一步重点|Linux、C++、ROS 2、ros2_control，关节状态与命令接口|
|**数据与调试工具**|尽早掌握|Python、NumPy、日志分析、自动化测试、延迟和跟踪误差分析|
|**机器学习与深度学习**|先学基础，再按方向深入|训练与推理、过拟合、张量、归一化，能运行并理解一个小模型|
|**LLM微调、多Agent、分布式训练**|当前可以靠后|只有决定转向相关岗位时，再系统投入|

我最建议你做的第一个项目，是把一条关节控制链路打通并测清楚。

- 从上位机控制一个关节，读取位置、速度、电流和故障状态。
- 接入统一接口，条件合适时接到 ros 2_control。
- 测量命令到反馈的延迟、周期抖动、跟踪误差和通信异常后的行为。
- 再接一个简单轨迹生成器，之后尝试替换为现成的学习策略。


自己的瓶颈究竟在通信、控制、接口，还是模型，而不是先学一大套算法却不知道用在哪里。


**对你的具体建议是：主线继续走机器人底层与控制系统，机器学习作为逐步接上的能力。**先争取做到“能让上层算法在真实关节上稳定运行”，再决定是否深入到“自己训练算法”。这比现在同时追 LLM、深度学习和强化学习，更能利用你已经积累的经验。

继续沿机器人底层方向发展，同时逐步补控制和 AI 部署知识。把“具身智能会怎样发展”留作行业判断，把“自己能否解决越来越完整的实机问题”作为职业主线。
