网络保持条件：接收到本部件相关的诊断报文（只判断 ID，不判断内容和长度
网络释放条件：诊断超时（未接收或者未发送本部件相关的诊断报文，超时 6 s）

诊断报文的物理寻址和功能寻址都可以保持网络
保持源只有一个诊断报文，唤醒源也只有一个 CANNM 唤醒。

（跳转条件：- **Repeat Message 定时器到期**，当前配置为 **4 秒**。 **本节点仍有有效网络请求**，即 `NetworkReqState_en` 为 `CANNM_NETWORK_REQUESTED_E`。）

| 取值                          | 含义                    |
| --------------------------- | --------------------- |
| `CANNM_NETWORK_REQUESTED_E` | 本节点有通信需求，主动请求保持网络     |
| `CANNM_NETWORK_RELEASED_E`  | 本节点无主动通信需求，允许网络进入休眠流程 |
![](assets/2026.09.17%20%20奇瑞%20NM%20新需求/file-20260917175714639.png)


明白了，也就是说 RMS 这里会根据自己本部件是否有通信的需求（诊断当然是通信的需求），选择是否进 normal operation 还是 ready sleep

DCM 中的 代码处理链路是：

Dcm 接收诊断请求，满足激活诊断条件
  → ComM_DCM_ActiveDiagnostic()
  → DiagnosticRequestState_b = COMM_ACTIVE_DIAGNOSTICS
  → ComM 周期处理，调用 Nm_NetworkRequest()
  → CanNm_NetworkRequest()
  → NetworkReqState_en = CANNM_NETWORK_REQUESTED_E
  
因此，**Repeat Message 的 4 秒到期时，必须仍有有效诊断保持请求，才会进入 Normal Operation。之前收发过诊断报文，但保持请求已经释放，则进入 Ready Sleep。**

### 发现问题：当前代码中即使一直发诊断报文，仍然无法进入 NO 状态。

Dcm_ActiveDiagnosticState_en = DCM_COMM_NOT_ACTIVE
    → Dcm 不通知 ComM 激活诊断保持
DiagnosticRequestState_b = FALSE
    → 没有主动网络请求
NetworkReqState_en = CANNM_NETWORK_RELEASED_E
    → NM 保持 Ready Sleep

| 变量                                               | 含义                         |
| ------------------------------------------------ | -------------------------- |
| `Dcm_ActiveDiagnosticState_en`                   | 功能开关：允许 Dcm 通知 ComM 激活诊断保持 |
| `ComM_ChannelStruct[0].DiagnosticRequestState_b` | 实际请求：当前是否需要诊断保持            |
`Dcm_SetActiveDiagnostic(TRUE)` 只打开开关，不会直接把 `DiagnosticRequestState_b` 置为 TRUE。

## 4)Normal Operation→Ready Sleep NM 

<mark style="background: #FF5582A6;">报文标志位置位清零且停发 NM 报文。</mark>


最后一次诊断收发后满 6 秒
→ NmDiagHold_Active = FALSE
→ ComM 判定无主动网络请求
→ Nm_NetworkRelease()
→ NetworkReqState_en = CANNM_NETWORK_RELEASED_E
→ CanNm_NormalOperationToRS()
→ 停止发送 0 x 60 B

6 秒超时，清除保持。

## 5)Ready Sleep →Prepare Bus-Sleep Mode 

NM 报文标志位已清零且已经停发 NM 报文。





## 6)Ready Sleep → Normal Operation 

Awake Reason 置位,如果此时保持源也是唤醒源, Wakeup Source 也置位,<mark style="background: #FF5582A6;">如果 只有保持源导致从 Ready Sleep 跳转到 Normal Operation,会出现 Wakeup Source 都为  0,只有 Awake Reason 置位的情况,比如诊断报文保持源。
</mark>
收到物理寻址 `0x72B` 或功能寻址 `0x7DF`，通过 CanTp 格式、长度校验后
```
刷新 6 秒诊断保持
→ ComM 请求网络
→ NetworkReqState_en = CANNM_NETWORK_REQUESTED_E
→ Ready Sleep → Normal Operation
→ 恢复每秒发送 0 x 60 B，Awake_Diag 置 1
```

诊断请求接收 / 诊断响应发送成功
                ↓
    NmDiagHold_NotifyActivity()
         刷新 6 秒保持时间
                ↓
    NmDiagHold_MainFunction()
                ↓
       ComM 仲裁网络请求
          ↙           ↘
   保持有效           保持超时
   请求网络           释放网络
      ↓                  ↓
 Normal Operation → Ready Sleep
 每秒发送 0 x 60 B       停止发送
