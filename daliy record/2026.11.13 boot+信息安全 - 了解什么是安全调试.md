# boot+信息安全 - 了解什么是安全调试

## TC 3 XX 是怎么安全调试的

debug interface 的配置在 UCB_DBG_ORIG (UCB 18) 中，Debug 的使能与否主要由 PROCONDBG 寄存器决定。此 UCB 为调试接口配置密码保护。


![](assets/2026.11.13%20boot+信息安全%20-%20了解什么是安全调试/file-20261113135114421.png)• Gate 1− 通过 OCDS 模块控制对 TriCore™调试的访问。On-Chip Debug System
• Gate 2− 通过 DMU 模块控制对 TriCore™调试的访问。
Gates 3 and 4
− 直接由 HSM 控制。
− 通过这两个门，HSM 可以锁定对 Host CPU 的调试访问权限，也可以关闭 HSM 自身的调试支持。
− 锁定机制由 UCB_HSM_ORIG 和 UCB_HSM_COPY 控制

大概原理就是这样了，想要更进一步，就去看寄存器的配置吧，感觉很简单这种东西。




## S 32 K 324 是怎么做的

支持两种 调试模式 
- **密码认证**：使用应用调试密码 ADKP 解锁调试访问。
- **挑战应答认证**：调试器根据随机挑战和密钥计算应答，认证通过后获得调试权限。

<mark style="background: #FF5582A6;">**芯片先限制调试口访问，调试器证明自己持有正确的密码或密钥后，芯片才开放调试权限。**</mark>
它由芯片的启动与安全机制执行，不能只靠 APP 启动后关闭调试引脚。
### **采用 HSE 的实现流程如下：**

1. **开发阶段准备安全配置**  
    安装并初始化 HSE 固件，在允许配置的生命周期阶段完成密钥和认证方式设置。
    
2. **写入调试密钥 ADKP**  
    通过 HSE 的 `SET_ATTR` 服务设置 `HSE_APP_DEBUG_KEY_ATTR_ID`，写入 128 位 ADKP。密钥由受控的生产工具管理，避免直接硬编码进 APP。
    
3. **选择认证方式**  
    通过 `HSE_DEBUG_AUTH_MODE_ATTR_ID` 配置：
    
    - **密码模式**：调试器提交密码，芯片验证。
    - **挑战应答模式**：芯片发出随机挑战，调试器使用密钥计算应答，芯片验证；不需要直接提交密钥。
4. **推进芯片生命周期**  
    按芯片规定推进到需要调试认证的阶段，例如 `OEM_PROD` / `IN_FIELD`，让调试保护生效。**仅写入密钥不等于完成调试口保护。**
    
5. **在调试器连接前执行认证**  
    TRACE 32 等工具先运行配套的认证流程，成功后再连接内核、读写内存和设置断点。认证状态在上电或破坏性复位后失效，需要重新认证。[参考 PEmicro 官方实现说明](https://www.ht.pemicro.com/learningcenter/contents.cfm?content_id=82)
    

挑战应答过程可以理解为：

```
芯片 → 调试器：随机挑战
调试器：用持有的密钥计算应答
调试器 → 芯片：应答
芯片：验证通过 → 开放调试权限
```

工程中的 [HSE 属性定义 (line 461)](E:/github/ECAS_qirui_Single_Chamber/BasicSoftware/integration/mcal/src/modules/Crypto_43_HSE/inc/interface/inc_services/hse_srv_attr.h:461) 已有相关接口。真正落地主要需要增加**生产密钥配置流程、生命周期配置流程，以及调试器认证脚本**。

需要在方案阶段注意：ADKP、认证模式和生命周期涉及 OTP 或单向变更，应先验证完整的“锁定—认证—调试”流程，再固化量产配置。
