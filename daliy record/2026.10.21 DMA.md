# DMA 


DMA（Direct Memory Access，直接存储器访问）是一种硬件搬运数据的机制：CPU 配置好搬运规则后，DMA 就能在外设与内存之间传输数据，无需 CPU 逐个读写。

以单片机采集 ADC 数据为例：

|方式|数据怎么进入内存|
|---|---|
|不使用 DMA|CPU 读取 ADC 结果，再写入数组，反复执行|
|使用 DMA|CPU 提前配置好，DMA 按 ADC 请求将结果写入数组|


ADC 转换结果 → DMA 搬运 → 内存缓冲区
                              ↓
                      CPU 处理采样数据


一次典型的 DMA 传输过程是：

1. **CPU 配置**：源地址、目标地址、数据宽度、传输数量，以及触发请求。
2. **DMA 搬运**：例如 ADC 每完成一次转换，就请求 DMA 搬运一个采样值。
3. **通知 CPU**：达到半满、完成或出现错误时，可以产生中断。

> [!NOTE]
> 它的主要好处是**减少 CPU 搬运数据的负担和频繁中断**。但 DMA 只负责搬运，数据计算仍由 CPU 完成；CPU 也需要协调好缓冲区，避免在 DMA 尚未写完时读取数据。

> [!NOTE] 为什么DMA也能访问RAM和外设
> RAM 和外设寄存器都有地址。CPU 可以通过地址访问它们，DMA 控制器也有发起总线访问的能力。




DMA的硬件操作：

从源地址读取 → 通过片内总线 → 写入目标地址


> [!NOTE] 注意
> CPU 与 DMA 仍然共享部分总线和存储资源，因此 DMA 运行时也可能发生总线竞争。


![](assets/2026.10.21%20DMA/25708a31edd4dd9e32bccd346a6971ae.png)

实线表示数据流，虚线表示配置或请求。

SPI 满足发送请求条件
        ↓
请求经过 DMAMUX 到达 DMA 通道
        ↓
DMA 根据配置执行一次搬运
        ↓
SPI 继续发送，后续请求继续推动搬运




SPI0 TX 请求 → DMA 通道 0
SPI0 RX 请求 → DMA 通道 1
DMAMUX 传递的是请求信号，实际数据由 DMA 通过总线读写。

### DMA可以响应哪些外设

|外设或模块|DMA 可以配合做什么|
|---|---|
|**SPI**|搬运发送、接收数据|
|**UART 串口**|搬运发送、接收数据|
|**I²C**|搬运发送、接收数据|
|**ADC、BCTU**|搬运采样结果|
|**FlexCAN**|响应硬件支持的 CAN 数据传输请求|
|**SAI 音频接口**|搬运音频发送、接收数据|
|**QuadSPI**|配合收发缓冲区搬运数据|
|**eMIOS、SIUL2、LCU 等**|用定时、引脚事件或逻辑事件触发搬运|


### 谁触发，如何搬运？

- **谁触发搬运**：由外设请求和 DMAMUX 决定。
- **搬什么数据、搬到哪里**：由 DMA 通道的源地址、目标地址等配置决定。


> [!NOTE]  顺丰
> DMA 是芯片内多个模块共享的搬运硬件；SPI 只是其中一个使用者。
> 


### 外设请求触发搬运的条件是什么？

通常是外设的硬件状态满足某个条件，例如：**发送缓冲区需要补数据、接收缓冲区里有数据、ADC 转换完成。** 外设检测到条件后，自动产生 DMA 请求。


ADC 开始转换
      ↓
转换完成，结果寄存器中出现有效采样值
      ↓
ADC 产生 DMA 请求
      ↓
DMA 读取结果，写入 RAM 中的采样数组


① SPI 收到一项数据，放入接收 FIFO
② SPI 发出 RX DMA 请求：“这里有数据，请取走”
③ DMA 读取 SPI 接收寄存器，把数据写入 RAM
④ FIFO 中的数据被取走；后续收到数据，再继续请求

```

Sequence → Job → Channel 和硬件单元 → SPI 0

调用继续向下，到达 `Lpspi_Ip_AsyncTransmit()`。驱动发现当前硬件单元的 `DmaUsed = TRUE`，就走 DMA 分支：

④ 应用通过 SPI 接口判断完成

- `SPI_SEQ_PENDING`：尚未完成。
- `SPI_SEQ_OK`：序列成功完成。
- `SPI_SEQ_FAILED`：传输失败。
