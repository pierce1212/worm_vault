# 特定帧唤醒
![](assets/2026.08.04%20奇瑞休眠唤醒（参考奇瑞需求）/file-20260804151900636.png)


不完全是“Byte 2 只要非零就唤醒”，准确条件是：

```
(DataByte[2] & 0x1F) != 0
```

也就是索引 `2`（第 3 个数据字节）的低 5 位任意一位为 `1` 才满足：

- `0x01、0x10、0x1F、0x21`：满足
- `0x20、0x40、0x80`：不满足

此外还必须同时满足：

- CAN ID：`0x600–0x6FF`
    - 配置基准 ID= `0x616`
    - ID Mask= `0x0FF`
    - TJA 1145 的 ID Mask 中 `1` 表示“不关心”，所以低 8 位任意，高 3 位固定为 `0x6`
- DLC= `8`
- PN 选择性唤醒已经激活

项目中生成的寄存器也确实是 Data Mask 2= `0x1F`：  
[CanTrcv_PBcfg.c (line 58)](E:/github/ECAS_qirui_Single_Chamber/BasicSoftware/src/bsw/CanTrcv/CanTrcv_PBcfg.c:58)

虽然 ARXML 里的初始 `CanTrcvPnEnabled=false`，但休眠前代码会主动执行：

```
CanTrcv_SetPNActivationState(CANTRCV_PN_ENABLED);
```

见 [BswM_Integration.c (line 207)](E:/github/ECAS_qirui_Single_Chamber/BasicSoftware/integration/src/bsw/BswM/user/BswM_Integration.c:207)。因此正常执行这条休眠路径且 SPI 配置成功后，PN 过滤会生效。

所以最终结论是：

> **<mark style="background: #FF5582A6;">收到 `0x600–0x6FF`、DLC=8，并且第 3 个数据字节的低 5 位至少有一位为 1，可以触发 TJA 1145 选择性唤醒。</mark>**

但这只解决“硬件唤醒”。唤醒后当前 CanIf 仍只接收 `0x616`，因此还不能保证对范围内每个 ID 都发送 `0x60B`；CanIf 范围过滤仍需调整。

TJA 1145 的数据唤醒规则可参见 [NXP TJA1145 数据手册](https://www.nxp.com/docs/en/data-sheet/TJA1145A.pdf)。
