## 实际执行逻辑

### 1. 收到 NM 报文

CAN 接收中断最终进入：

[CanNm_RxIndication.c (line 355)](E:/github/ECAS_qirui_Single_Chamber/BasicSoftware/src/bsw/CanNm/src/CanNm_RxIndication.c:355)

主要动作是：

```
RamPtr_ps->RxIndication_b = TRUE;
RamPtr_ps->RxStatus_b = TRUE;
```

这里不会直接调用 `CanNm_PassiveStartUp()`，只是设置接收标志。

### 2. 等待 CanNm 10 ms 主函数

BSW 任务周期为 10 ms。`CanNm_MainFunction()` 读取并清除接收标志：

[CanNm.c (line 163)](E:/github/ECAS_qirui_Single_Chamber/BasicSoftware/src/bsw/CanNm/src/CanNm.c:163)

```
PduRxInd_b = RamPtr_ps->RxIndication_b;
RamPtr_ps->RxIndication_b = FALSE;
```

如果 CanNm 处于 Bus Sleep，并且发现收到 NM，就调用：

```
Nm_NetworkStartIndication()
```

对应逻辑在 [CanNm_Inl.h (line 373)](E:/github/ECAS_qirui_Single_Chamber/BasicSoftware/src/bsw/CanNm/api/CanNm_Inl.h:373)。

这一段理论等待：

```
0～10 ms
```

### 3. Nm 通知 ComM

调用链同步执行：

```
Nm_NetworkStartIndication
→ ComM_Nm_NetworkStartIndication
```

ComM 设置被动请求：

[ComM_Nm_NetworkStartIndication.c (line 84)](E:/github/ECAS_qirui_Single_Chamber/BasicSoftware/src/bsw/ComM/src/ComM_Nm_NetworkStartIndication.c:84)

```
PassiveRequestState_u8 |= 0x04;
```

此时只是置标志，也不会立即调用 PassiveStartUp。

### 4. 等待下一次 ComM 10 ms 主函数

当前 10 ms BSW 任务中的调用顺序是：

```
CanSM_MainFunction
→ CAN Mode MainFunction
→ ComM_MainFunction
→ CanNm_MainFunction
```

见 [Rte.c (line 20913)](E:/github/ECAS_qirui_Single_Chamber/BasicSoftware/src/rte/gen/Rte.c:20913)。

关键点是：

```
ComM在CanNm之前运行
```

所以 CanNm 设置 ComM 被动请求时，本周期的 ComM 已经执行完了。这个请求必然等到下一个 10 ms 周期才能处理。

### 5. ComM 处理被动请求

下一次 ComM 主函数读取：

```
PassiveRequest_b =
    (PassiveRequestState_u8 > 0);
```

然后执行状态转换：

```
COMM_NO_COM_NO_PENDING_REQUEST
→ COMM_NO_COM_REQUEST_PENDING
→ 检查CommunicationAllowed_b
→ COMM_FULL_COM_NETWORK_REQUESTED
→ COMM_FULL_COM_READY_SLEEP
→ Nm_PassiveStartUp()
→ CanNm_PassiveStartUp()
```

最终调用位置：

[ComM_LChannelMainFunction.c (line 819)](E:/github/ECAS_qirui_Single_Chamber/BasicSoftware/src/bsw/ComM/src/ComM_LChannelMainFunction.c:819)

## 理论时间

如果 `CommunicationAllowed_b` 已经为 TRUE：

```
Rx → CanNm_MainFunction     = 0～10 ms
等待下一次ComM_MainFunction = 约10 ms
其他同步函数调用             ≈ 很小
--------------------------------------
理论总时间                   ≈ 10～20 ms
```

如果同一次启动直接测得约 41 ms，说明额外等待了约两个 10 ms 周期。重点检查：

```
ComM_ChannelStruct[0].CommunicationAllowed_b
ComM_ChannelStruct[0].ChannelState_e
ComM_ChannelStruct[0].PassiveRequestState_u8
ComM_ChannelStruct[0].BusSmMode_u8
```

最可能是 ComM 收到被动请求后，`CommunicationAllowed_b` 还没有及时变成 TRUE，等待 BswM/CanSM 通信状态准备完成。
