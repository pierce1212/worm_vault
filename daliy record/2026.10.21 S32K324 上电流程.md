**S 32 K 324 从上电到运行程序，要经过“供电建立 → 硬件复位时序 → 芯片内部启动固件 → 用户程序启动代码 → main”这条链。** 前面由硬件和 NXP 固件完成，后面才轮到你工程里的代码。



# 上电流程


① 电先到达供电电路，此时还没有你的 C 代码参与。
可以把 MCU 看成内部有多种工作电压的电路，而不是只接一根电源线就全部直接使用同一个电压。

|电源名称|在 S32K324 中的作用|
|---|---|
|`VDD_HV_A`|主 I/O 和模拟电源|
|`VDD_HV_B`|另一组 I/O 电源|
|`V15`|约 1.5 V 的逻辑供电节点|
|`V11`|约 1.1 V 的内核逻辑电源域|
|`V25`|内部稳压得到的约 2.5 V Flash 电源|
汽车电源经过板上电源芯片生成 MCU 所需电压后，以上过程才能开始；汽车电池电压不会直接加到 MCU 的这些供电引脚上。


**② 电压还在上升时，硬件先让芯片保持复位。**

上电瞬间，供电从接近 0 V 开始爬升。这个阶段，逻辑电路还不具备可靠运行条件。
芯片内部的 **POR——Power-On Reset，上电复位电路**，以及其他电源监测、复位控制逻辑，负责约束启动过程。满足相应条件后，芯片才继续退出复位。


③ 刚启动时，时钟从内部 FIRC 来。
CPU 执行指令需要时钟。S 32 K 3 默认复位配置使用内部 **FIRC**，其标称频率为 **48 MHz**，因此最初的启动并不需要先由你的代码把外部晶振和 PLL 配好。

④ 用户 M 7 程序之前，先执行 NXP 的 SBAF。

S 32 K 324 的启动过程里有一层 **SBAF，Secure Boot Assist Flash**。这是芯片提供的启动固件，涉及 HSE 子系统的 Cortex‑M 0+；完成相应启动处理后，再让 Cortex‑M 7 用户核接手。

SBAF 会解析 Flash 中的 **Boot Header，也叫 Image Vector Table，映像向量表**。其中包含：

- 启动标记，例如 `0x5AA55AA5`；
- 启动配置字；
- Cortex‑M 7 核的启动地址信息。

是否涉及 HSE 安全启动认证，要看芯片和镜像的配置，不能只看到“SBAF”就认定项目已经启用了应用认证

|表|用途|
|---|---|
|NXP Boot Header／映像向量表|让 SBAF 知道如何启动用户核|
|Cortex‑M 异常向量表|提供初始栈指针、复位处理函数及中断处理入口|


⑥ 到了 `Reset_Handler`，才开始建立运行 C 程序所需的环境。

```
Reset_Handler / _start
    ↓
关闭可屏蔽中断，进行基础寄存器和时钟门控设置
    ↓
设置 VTOR：告诉 CPU 异常向量表在哪里
    ↓
设置 MSP：建立当前核的栈
    ↓
处理启动阶段的 SWT 看门狗
    ↓
按配置初始化 SRAM、DTCM、ITCM 的 ECC
    ↓
init_data_bss()
    ├─ 把需要初始化的数据从 Flash 复制到 RAM
    └─ 清零指定的 BSS 区域
    ↓Cortex‑M7 复位时，会从向量表里读取入口地址。
SystemInit()
    └─ 配置中断路由，以及按编译选项处理 MPU、Cache 等
    ↓
main
    ↓
EcuM_Init()
```


## 如何找到首地址运行的？

Cortex‑M 7 复位时，会从向量表里读取入口地址。

| 存放位置       | 存储的内容    | CPU 用它做什么       |
| ---------- | -------- | --------------- |
| `B + 0x00` | 初始栈顶地址   | 初始化 MSP，也就是主栈指针 |
| `B + 0x04` | 复位处理函数地址 | 确定开始执行的位置       |
**CPU 不是执行 `B + 4` 位置的数据，而是把那里存放的数值当成入口地址，再去那个入口取指令。** Arm 的 Cortex‑M 7 手册明确规定，复位向量位于初始 VTOR 所指位置再加 `4` 字节


在 S 32 K 324 上，这个向量表基地址 `B` 又是谁提供的？

S 32 K 324 上电复位后，先进入芯片规定的内部启动路径，运行 NXP 提供的 SBAF。它再根据 Flash 中的 **Boot Header**，确定用户 M 7 核的启动配置。
以普通、非安全启动路径（`BOOT_SEQ = 0`）为例，Boot Header 的 ** `+0x0C` 字段**给出 M 7_0 的启动向量表地址。SBAF 根据它安排 M 7 的启动，使 M 7 的初始向量表位置对应这个地址。



SBAF 自己又是谁启动的？

**芯片的复位控制电路、处理器复位逻辑和预设启动入口，是芯片设计时就确定的。** 复位信号让相关硬件进入规定状态；启动条件满足、时钟运行后，硬件按照固定的启动规则发起最初的存储器读取，进入 NXP 的内部启动固件。

`Reset_Handler` 的名字，和上述机制是什么关系？

```
链接器确定 Reset_Handler 放在什么地址
        ↓
把这个地址填进向量表对应位置
        ↓
烧录工具把向量表和机器指令写入 Flash
        ↓
下次上电，硬件读取 Flash 中已经存在的地址数值
```


> [!`start` 和 `Reset_Handler` 是同一个位置的两个标签；到达这个位置后，CPU 执行的是 `cpsid i` 对应的机器指令] 
> 




**S 32 K 324 的 SBAF 出厂时就由 NXP 写好了。后续需要升级时，使用 NXP 提供的固件包和专门的更新流程；日常编译、烧录 APP 通常不会更新它。**


**① 它存在哪里？**

SBAF 存在芯片内部的 **HSE Code Flash 区域**。它属于 Flash 中的固件，因此具有受控更新能力，并不是完全不可修改的硬件逻辑。NXP 的出厂内存布局图中已经包含 `SECURE BAF`。[NXP 安全启动培训资料，第 17 页](https://community.nxp.com/pwmxy87654/attachments/pwmxy87654/S32K/30542/2/12_S32K3xx_Security_Overview_and_Bring_Up_Training.pdf)

这也解释了：**你买到芯片后，即使尚未烧入自己的 APP，芯片也已经有 SBAF 可以运行。**

**② 开发人员通过什么更新它？**

NXP 提供了 `S32K3_HSE_DemoExamples` 示例包，其中有专门的更新工程，例如：

```
Device_Configuration/
    S32K344_SBAF_UPDATE/
    S32K344_HSE_FW_UPDATE/
```

这是 NXP 官方列出的示例名称。用于 S 32 K 324 时，需要按配套文档确认芯片型号、硅版本和固件兼容性，不能仅因为同属 S 32 K 3 就直接套用。[NXP 官方更新说明](https://community.nxp.com/t5/S32K/How-update-SBAF-and-HSE-FW-via-OTA/td-p/1818372?profile.language=en)

可以把更新过程理解为：

```
取得匹配的 NXP 固件包
        ↓
在目标 MCU 上运行配套更新程序
        ↓
按 NXP 更新协议提交镜像、完成更新
        ↓
复位并检查版本、启动结果
```

调试器或 OTA 可以承担更新程序、镜像的传输，但**把文件传进芯片，和完成 SBAF 安装，是两件事**。

**③ 它会不会跟着 HSE 固件一起更新？**

这取决于存储配置：

|配置|SBAF 更新方式|
|---|---|
| `FULL_MEM` |支持单独更新 SBAF|
| `AB_SWAP` |SBAF 包含在对应的 HSE 固件中，随 HSE 固件更新；不走独立 SBAF 更新方式|

这是 NXP 技术支持明确说明的区别。[NXP 对 FULL_MEM 与 AB_SWAP 更新方式的解释](https://community.nxp.com/t5/S32K/How-update-SBAF-and-HSE-FW-via-OTA/td-p/1818372?profile.language=en)

联系你的工程：我们前面看到的项目 Bootloader、APP 启动汇编和 Boot Header，分别是项目程序、启动代码和启动配置数据。**修改 Boot Header 是改变 SBAF 读取的配置，不等于修改 SBAF 本身。**
