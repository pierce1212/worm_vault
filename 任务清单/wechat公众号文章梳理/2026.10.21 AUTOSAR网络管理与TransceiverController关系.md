当 BAT（等价于 KL 30，本例不用 KL 15）给 Transceiver 1145 供电后，Transceiver 1145 的 INH 引脚激活 3 V 电源管理模块，进而给主芯片供电，当主芯片供电以后，程序开始运行，<mark style="background: #FF5582A6;">但此时网络处于 BSM（Bus Sleep Mode</mark>），ECU 并不能立马外发报文，需要对唤醒事件进行有效性验证，避免因总线抖动或者其他干扰造成的 ECU 无效唤醒

T<mark style="background: #FF5582A6;">ransceiver 1145 需要切换到 Normal Mode</mark>
ECU 想正常的收发报文需要 Transceiver 1145 和 Controller 进入各自的工作状态。此时 Transceiver 1145 才能将模拟信号和数字信号进行转换


![](assets/2026.10.21%20AUTOSAR网络管理与TransceiverController关系/file-20261021142326840.png)


1. 当前代码中在 EcuM 初始化中就会设置唤醒事件。
![](assets/2026.10.21%20AUTOSAR网络管理与TransceiverController关系/file-20261021144245002.png)


（上电默认就是 CAN 唤醒）



2. EcuM_CheckWakeup➡CanIf_CheckWakeup 实际上已经在 EcuM 的主函数中运行了。
3. CanTrcv_CheckWakeup  中实际是调用的  CanTrcv_CheckWakeup_SPI
4. EcuM调用EcuM_StartWakeupSources接口，<mark style="background: #FF5582A6;">该操作的实质是使得Controller进入Start状态</mark>





5. 至此Transceiver1145和Controller均进入了对应的工作状态，ECU具备了收发报文的能力

# 差异

|环节|当前项目|对比|
|---|---|---|
|收发器|使用 TJA1145，通过 SPI 控制|与文章一致|
|唤醒事件上报|CanTrcv 周期检查可调用 `EcuM_SetWakeupEvent`；启动时 ExeMgr 也会读取唤醒原因并上报|入口更丰富|
|唤醒源检查|存在 `EcuM_CheckWakeup → CanIf_CheckWakeup → CanTrcv_CheckWakeup`|有相同调用链，但不代表每次唤醒都按文章图的顺序经过|
|启动硬件|`EcuM_StartWakeupSources → CanSM_StartWakeupSource`，由 CanSM 推进收发器 NORMAL、控制器 STOPPED → STARTED|核心一致，项目显式经过 CanSM|
|验证后通信|控制器启动后，还要通过 CAN 唤醒验证，再推进正常通信|文章没有展开这些细节|

1. 先让 CanSM 进入“唤醒验证”状态
2. 周期任务按顺序准备收发器、停止并启动 Controller

```
TRCV_NORMAL
  → CanSM_NormalTrcv()
  → 收发器切换到 NORMAL

CC_STOPPED
  → CanSM_StopCtrl()
  → CanIf_SetControllerMode(controllerId, CAN_CS_STOPPED)

CC_STARTED
  → CanSM_StartCtrl()
  → CanIf_SetControllerMode(controllerId, CAN_CS_STARTED)
```


3. STARTED 请求一直传到底层 FlexCAN 驱动

```
CanSM_StartCtrl(network)
  → 从网络配置中取得 controllerId
  → CanIf_SetControllerMode(controllerId, CAN_CS_STARTED)
  → Can_Integn_SetControllerMode(...)
  → Can_SetControllerMode(...)                 // 宏映射
  → Can_43_FLEXCAN_SetControllerMode(...)
  → Can_43_FLEXCAN_Ipw_SetControllerToStartMode(...)
  
```
