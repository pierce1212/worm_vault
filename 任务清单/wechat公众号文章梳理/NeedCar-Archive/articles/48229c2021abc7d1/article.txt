1、什么是FIFO
FIFO
：First Input First Output，即：先进先出，是一种
数据结构
。在CAN Driver部分，CAN报文的收/发配置有多种选择，其中，FIFO就是一个选配项。在实际的项目开发中，FIFO适用于哪些场景呢？
答
：
队列诊断
。目前，有些OEM为了提高App程序刷些的效率，提出了队列刷写的要求。因此，Bootloader也需要相应的支持队列刷写功能。队列刷写意味着：Bootloader需要接收多个诊断指令，然后按照诊断指令收到的先后顺序处理，不能错序。对于此场景，使用FIFO接收和发送处理就是一种不错的选择。

2、Basic CAN和Full CAN的区别
不管是Basic CAN还是Full CAN，均需要消耗硬件资源HOH，HOH也就是常说的邮箱（mailbox），进一步细化HOH，又分为HRH（CAN hardware receive handle）和HTH（
CAN hardware transmit handle
）。
Full CAN
：一个
HOH只能接收或者发送
一个
CAN报文（或者说一个L-PDU），HOH可以配置成HTH或者HRH。
Basic CAN
：一个HOH接收或者发送
多个
CAN 报文
（或者说多个L-PDU）
，
HOH可以配置成HTH或者HRH
。
HOH实质就是存放收/发CAN报文信息的RAM区，该区域可以按需所取，也就是说：根据项目的情况（收/发的CAN报文数目），配置Message RAM使用的空间，
实际工程，建议全部使用
。
Message RAM
就好比一块蛋糕，总大小是一定的，你能吃多少，就切多少。根据处理CAN报文的方式不同，

4、Basic CAN使用FIFO结构引发的工程问题
（一）问题现象
一个200ms周期的
接收报文
（应用报文，eg：PDU_A，CAN ID = 0x100），实际接收需要6.4s。
（二）原因分析
排查发现：PDU_A配置成Basic CAN类型（只接收PDU_A），使用FIFO模式，且depth = 32，中断接收。而接收时，
只有32个缓存区满了，达到水印(watermark)位置才触发接收中断
。所以使得PDU_A由200ms变成200 * 32 = 6.4s接收一次。PDU_A配置如下所示：
（三）解决策略
修改PDU_A配置的Depth，配置Depth = 1，即：每次接收到PDU_A就触发中断。
