信息安全：安全启动的信任链如何建立？

1、包含HSM程序与否的区别
在没有使用信息安全项目中，芯片内部的程序一般包含User Bootloader（这里不延伸Boot Manager）和User Application，如下所示：
对于没有信息安全的控制器，程序的启动流程，示意如下：
当芯片上电以后（PowerOn），CPU就开始执行程序。那么，CPU查找的第一程序是谁呢？简单理解，CPU查找的第一个程序是User Bootloader程序，之后，在
User Bootloader中检查进入User Application程序的条件（比如：APP是否有效等），如果满足进入App条件，则程序进入
User Application。之后，控制器可以执行对应的功能。
当项目要求使用信息安全（假设芯片支持HSM）以后，芯片的软件程序就不再只是
User Bootloader和User Application，它还需要包含
HSM Bootloader和HSM Application，示意如下：
当芯片包含了HSM以后，不仅软件程序增加了。一般来说 ，使用的CPU核心数量也会增加。信息安全的设计中，需要做到物理隔离，一般来说，信息安全会有独立的CPU和内存等外设。有些芯片中，Host CPU和HSM CPU可能使用不同的架构和指令集，更多细节可以参考前文《

在实际的项目中，还有一种启动方案：
串行启动
，如何理解呢？示意如下：
当使用串行的启动方案时，HSM CPU先使能，并且进入HSM Bootloader程序，同时，将Host CPU暂停（Halt）。当HSM Application程序验证用户程序（比如：
User Bootloader
）安全可信时（没有被篡改 ），HSM CPU释放
Host CPU，此时，
Host CPU才能进入
User Bootloader程序。
注意
：串行启动方案中，
HSM CPU是释放（Release）Host CPU
，
不是跳入（Jump）用户程序
。释放的意思就是，让Host CPU去运行对应的程序。如果HSM CPU和Host CPU的架构不同，使用的指令集不同，
HSM CPU无法运行Host的程序，Host  CPU也无法运行HSM程序。
