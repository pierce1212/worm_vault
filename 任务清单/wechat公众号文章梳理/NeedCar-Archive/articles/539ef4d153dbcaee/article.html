嵌入式开发：DMA何时使用更好？

开心果 Need Car · 2022-12-24T00:06:00+08:00 · 微信原文

嵌入式开发中，DMA（Direct Memory Access）的使用已经相当普遍。eg：SPI（QSPI）+DMA，UART+DMA，Ethernet+DMA等，DMA的使用似乎已经成为标配。我们清楚：使用DMA的主要目的是想释放CPU，将搬运数据的活交给DMA干，以便于CPU处理更重要的事情。但是，工程中，Copy数据的动作真的完全放手给DMA就可以吗？本文进行如下几点讨论：

1、精简的DMA搬运驱动Code

2、DMA概念基础

3、何时使用DMA更合适？

提示：基于英飞凌TC3xx。

1、精简的DMA搬运驱动Code

搞懂DMA并不难，难得是如何结合项目实际，恰当得使用DMA，起到事半功倍的目的。让DMA干活，最简单的就是告诉其4点内容：
  1. Source Address；
  2. Destination Address；
  3. Data Width;
  4. DMA Request。
如下所示：

DMA负责将数据由Origin Position搬运到Destination Position，这里的Position可以是内存区，也可以是外设的RAM区。

（一）DMA Code示例

举例：将一个数据宽度为32 bit的数据，由源地址（DMA_SAD_Adrr）搬运到目的地址（DMA_DAD_Adrr），使用软件触发请求。对应的示意代码如下所示：

/* source address */DMA_SADR000.U = DMA_SAD_Adrr;/* destination address */DMA_DADR000.U = DMA_DAD_Adrr;/* channel data width,channel data width to 32 bit */DMA_CHCFGR000.U = (0x2 << 21);/* disable DMA hardware requests */DMA_TSR000.U |= (1 << 17);/* initiate DMA software request */DMA_CHCSR000.U |= (1 << 31);

2、DMA概念基础

（一）数据搬运结构

DMA Move：DMA搬运数据的最小单位是Move，一个完整的DMA Move包括Read Move和Write Move两部分。Read Move和Write Move要保持数据宽度（Width）一致，即：1 byte（8 bit）、2 byte（16 bit）、4 byte（32 bit）、8 byte（64 bit）、16 byte（128 bit）、32 byte（256 bit）。Read Move和Write Move关系如下所示：

DMA Transfer：如果想进一步的扩大数据的搬运量，则需要使用DMA Transfer，一个DMA Transfer可以包含多个DMA Move（注意，TC3xx中规定一个DMA Transfer可以包含1, 2, 3, 4, 5, 8, 9 或者 16 DMA moves）。
DMA Transaction：一个DMA Transaction可以包含多个DMA Transfer，但是，至少要包含一个DMA Transfer。
Linked List：一个Linked List可以包含多个DMA Transaction。

将上述的概念，结合DMA的搬运过程理解一下，如下所示：

解释：

一个DMA Transaction包含n个DMA Transfer，搬运引擎（ME:Move Engine）执行搬运动作。ME每执行一次DMA Transfer，MEmCHSR (m=0-1)寄存器的TCOUNT位域数值减1（注意：TCOUNT数值由CHCFGR.TREL加载）。完成搬运以后（Transfer Count = 0），如果对应的DMA Channel使能了Interrupt，则进入对应的中断例程（eg：告知CPU，数据搬运完成）。

（二）DMA Channel模式

DMA的每个Channel主要包含两种模式：Single Mode和Continuous Mode。
Single Mode：完成一次DMA Transaction以后，由硬件自动关闭DMA的硬件请求。
Continuous Mode：完成一次DMA Transaction以后，硬件不会自动关闭DMA的硬件请求。

（三）DMA使用示例

举例：将源地址（空间大小 4 * 100 byte）数据搬运到目的地址（空间大小 4 * 100 byte）。源地址和目的地址连续，搬运的数据宽度为4 byte（32 bit）。示例代码如下所示：

{    Ifx_DMA_CH_CHCFGR chcfgr;    chcfgr.U          = 0;    /* DMA channel TCS transfer reload value to control the number of DMA      * transfers in a DMA transaction.25 * 4 = 100 32-bit data */    chcfgr.B.TREL     = 25;    /* 010B One DMA transfer has 4 DMA moves */    chcfgr.B.BLKM     = 2;    /* One DMA request starts a complete DMA transaction. */    chcfgr.B.RROAT    = 1;    /* Single_Mode, is selected for DMA channel.*/    chcfgr.B.CHMODE   = 0;    /* channel data width,channel data width to 32 bit */    chcfgr.B.CHDW     = 2;    /* 000B No pattern compare operation. */    chcfgr.B.PRSEL    = 0;    DMA_CHCFGR000.U = chcfgr.U;}
{    Ifx_DMA_CH_ADICR adicr;    adicr.U       = 0;    /* 000B Address offset is 1 x CHDW */    adicr.B.SMF   = 0;    /* 1B Address offset will be added. */    adicr.B.INCS  = 1;    /* DMA channel TCS circular buffer source address update control bit */    adicr.B.CBLS  = 0;    /* 0B Source circular buffer disabled. */    adicr.B.SCBE  = 0;    /* 000B Address offset is 1 x CHDW */    adicr.B.DMF   = 0x00;    /* 1B Address offset will be added. */    adicr.B.INCD  = 1;    adicr.B.CBLD  = 0;    adicr.B.DCBE  = 0;    /* DMA channel TCS shadow control */    adicr.B.SHCT  = 0;    /* Time Stamp */    adicr.B.STAMP = 0;    /* DMA channel TCS source buffer interrupt trigger enable/disable. */    adicr.B.WRPSE = 0;    adicr.B.WRPDE = 0;    /* DMA channel TCS interrupt control. */    adicr.B.INTCT =  0;    /* Interrupt Raise Detect Value */    adicr.B.IRDV  = 0;
    DMA_ADICR000.U = adicr.U;}/* source address */DMA_SADR000.U = DMA_SAD_Adrr;/* destination address */DMA_DADR000.U = DMA_DAD_Adrr;/* disable DMA hardware requests */DMA_TSR000.U |= (1 << 17);/* initiate DMA software request */DMA_CHCSR000.U |= (1 << 31);

3、何时使用DMA更合适？

如上的两个例子，大家已经感受到了，搬运数据这活，让DMA处理，似乎挺好。但是，我们也意识到，如果想让DMA干活，CPU首先要告诉DMA怎么干，即：DMA干活前的所有"准备"工作均由CPU"操心"，这势必需要耗费CPU的时间，所以，如果CPU需要Copy的数据量不大，或者说，CPU自己搬运数据花费的时间比"操心"DMA使能的时间还多，使用DMA就有点大可不必了。
