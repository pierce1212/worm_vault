功能安全E2E：MaxNoNewOrRepeatedData配置错误导致进入SYNC状态

开心果 Need Car · 2023-01-06T08:33:00+08:00 · 微信原文

工程中，E2E的问题相对来说比较少。不管是工具配置还是用户使用，E2E涉及的东西不是很多，E2E Library帮我们简化了很多工作，所以，犯错的机会比较少，但这并不是说不会有问题。本文，聊一个E2E的工程问题："MaxNoNewOrRepeatedData配置错误导致进入SYNC状态"。

1、问题描述

（一）MaxNoNewOrRepeatedData释义
先看一下Autosar对参数MaxNoNewOrRepeatedData的解释，如下所示：
什么意思呢？答：正常通信工况下，接收端预期不会超过的最大丢失或重复数据量，工程常用值：14。
MaxNoNewOrRepeatedData在E2E_P01配置位置示意如下所示：
static const E2E_P01ConfigType Config_<p>_<o> =  { 8, /* CounterOffset */   0, /* CRCOffset */   0x12, /* DataID */   12, /* DataIDNibbleOffset */   E2E_P01_DATAID_BOTH, /* DataIDMode */   64, /* DataLength */   1, /* MaxDeltaCounterInit */   14, /* MaxNoNewOrRepeatedData */   2, /* SyncCounterInit */ };

 （二）问题现象

某一时刻，接收端接收到的RC（Rolling Counter）没有累加，对应的UB（Update Bit）没有置位，如下所示：

调试发现：最终，E2E进入E2E_P01STATUS_SYNC状态，而算法识别到E2E_P01STATUS_SYNC状态以后，会有指示灯提示，并且限制车辆功能。

2、问题分析

当UB没有置位时，E2E的Check也就不再进行，但是，State->NoNewOrRepeatedDataCounter < 14，State->NoNewOrRepeatedDataCounter++。当下一次正常接收E2E数据时，会检查State->NoNewOrRepeatedDataCounter <=Config->MaxNoNewOrRepeatedData，如果条件为FALSE，则会进入E2E_P01STATUS_SYNC状态，如下所示：

就一次没有收到有效RC就进入E2E_P01STATUS_SYNC状态，这是不是太严苛了？答：是的。实际因为参数maxNoNewOrRepeatedData配置成了0，使得State->NoNewOrRepeatedDataCounter <=Config->MaxNoNewOrRepeatedData不成立（FALSE），导致进入E2E_P01STATUS_SYNC状态。
（一）MaxNoNewOrRepeatedData示例
假设配置MaxNoNewOrRepeatedData = 3，示例如下所示：
如上图，Cycle 9时，NoNewOrRepeatedDataCounter超过了MaxNoNewOrRepeatedData，Counter不再可信，进入E2E_P01STATUS_SYNC状态。所以，工程中，将E2E_P01STATUS_SYNC状态作为一种异常状态处理。

3、问题解决策略

修改配置参数MaxNoNewOrRepeatedData，本文推荐值：14。
