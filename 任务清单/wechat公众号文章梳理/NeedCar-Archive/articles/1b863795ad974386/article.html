编程会话中的 queued request：为什么“支持队列”意味着更高的接收能力要求？

开心果 Need Car · 2026-05-08T06:21:00+08:00 · 微信原文

在诊断通信规范中，Programming Session（编程会话）始终是一个被重点关注的场景。与普通诊断会话相比，编程会话涉及刷写、校验、下载等高风险、高负载操作，对 ECU 的通信能力、实时性和稳定性提出了更高要求。正是在这个背景下，一些OEM的规范引入了一项看似“苛刻”的要求：一旦 ECU 声称支持 queued request，它在编程会话中就必须能够以 CAN 协议允许的最小间隔接收 Single Frame（SF）。

理解这条要求，关键不在于“队列”本身，而在于能力与责任的对等关系。

queued request 本质上意味着什么？

从需求的角度看，queued request 并不是一条强制能力，而是一种实现选项。支持 queued request，意味着 ECU 在“当前无法立即处理请求”时，可以：

  • 正确接收请求

  • 缓存在内部队列（FIFO）中

  • 在合适的时机再进行处理

这本身已经说明 ECU 具有额外的缓冲、调度和请求管理能力。因此，需求的基本逻辑是：如果 ECU 宣称具备这种高级能力，它就不应再成为通信节奏上的瓶颈。

为什么要求“尽可能短的时间间隔”接收 SF？

常见的需求中会要求：在编程会话中，如果 ECU 支持 queued request，应当以 CAN 协议本身允许的最短时间间隔接收 Single Frame。

这里的关键措辞有两个：

  • “handle receiving” ——强调的是“接收能力”，而不是“处理或响应速度”

  • “as short time apart as CAN protocol allows” ——下限由 CAN 协议决定，而不是 ECU 软件设计决定

换句话说，ECU 不能因为内部实现原因，主动拉大 SF 之间的间隔或拒绝紧密到来的请求。

在 CAN 协议中，相邻报文之间允许的最短间隔由最小 Interframe Space（IFS，帧间隔） 决定。专门点出这一点，意思非常明确：我们并不要求 ECU 超越物理和协议极限，但也不允许它比 CAN 协议更“慢”。

对应到实际的工程中，多数碰到的是这样的需求：

Queued physical requests aboved shall include Service-TransferData UDS $36 and Service-RequestTransferExit UDS $37 services at least.

解释：该需求明确了 queued physical requests 的最小覆盖范围。在编程会话中，若 ECU 声称支持 queued request，则至少应在 TransferData（$36）和 RequestTransferExit（$37）等核心刷写服务中支持该机制，以保障编程过程的鲁棒性。

为什么强调“同一发送方”和“不同发送方”都适用？

特别注意，这一要求既适用于同一发送方，也适用于不同发送方。这一表述并非多余，而是为了防止一种常见实现漏洞：当多个 Tester 或网关并发发送请求时，接收能力骤降。在真实系统中，以下场景非常常见：

  • 诊断仪 + 网关同时存在

  • 编程工具与监控工具并行工作

通过这一条款明确要求：queued request 的支持必须是“与发送方无关”的能力，而不是针对单一通信路径的特例。

那不支持 queued request 的 ECU 怎么办？

一般，需求并不会“一刀切”。相反，需求会给出一个明显更宽松的要求：

对于不支持 queued request 的ECU，在编程会话中，只需保证能够在不超过 P2server_max 的时间间隔内接收 Single Frame。这反映了在设计上的现实主义态度，并非所有 ECU 都有足够 RAM 和算力。对资源受限 ECU，只要求满足基本的 UDS timing 约束。因此，“支持队列”既不是强制选项，也不是无成本承诺。

  • 不支持 queued request，满足最基本的 P2server_max 即可

  • 支持 queued request ，必须具备 CAN 节奏级别的接收鲁棒性

这既保护了 Tester 的通信预期，也防止 ECU 通过“半支持队列”的方式规避性能责任。

总结

关于 queued request 的要求，真正关注的并不是“是否排队”，而是ECU 在编程会话中的通信鲁棒性和系统能力边界。通过差异化要求，明确传递了一个信号：queued request 是高级能力，对应的也是更严格的接收性能责任，而不是一个可以随意勾选的功能选项。
