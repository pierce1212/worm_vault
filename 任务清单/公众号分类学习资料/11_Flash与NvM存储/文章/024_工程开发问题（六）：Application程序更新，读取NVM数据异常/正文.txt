项目开发中，我们会遇到这样的需求：预留一定的NVM空间，存储一些关键参数。比如：DEM模块需要存储DTC对应的快照数据、拓展数据、状态位数据，某应用层(ASWC)需要存储车辆里程数等。
存储这些信息到NVM，主要是便于下次车辆启动时的再次使用。
根据参数的重要程度，可以选择不同的存储类型：
时时存储、事件存储、下电存储。
NVM模块作为重要信息的存储介质，角色分量自然不轻，当然，带来的问题也不容小觑。本文讨论一个NVM问题：
Application更新后，第一次从NVM读取数据
，参数值异常！
1
NVM、Application、RAM全局变量的内存分布
先认识一下本文要关注的几个重要存储区域：Application Code Area、NVM Area、RAM Area。
Application Code Area
：存放程序代码（非易失存储区，PFlash，比如：0x80000000~0x802FFFFF，3M）。
NVM Area
：存放关键参数（非易失存储区，EEPROM，比如：0xAF000000~0xAF0003FF，1K）。
RAM Area
：
存放关键参数
（易失存储区，比如：0x70000000~0x700003FF，1K）。
注意
：本文讨论的
NVM Area和
RAM A
rea的空间大小一致，这里的
RAM A

工程思考
在实际的工程项目中，此类问题需要分情况讨论：
1、使用参数默认值( = 0 / 0xFF)
如果Application程序更新后，要求RAM区中的参数使用默认值，比如：0或者0xFF。可以根据所使用的Block开辟一段等大小的PFlash空间存放初始值，当识别到
Application
程序更新或者NVM Block无效时，将PFlash中的初始值赋给RAM区参数；如果
Application
程序没有更新，且NVM参数有效，将NVM中参数赋给RAM区域，如下所示：
2、使用参数初始值
如果Application程序更新后，要求RAM区中的参数使用初始值，此种情况可能会复杂一些，因为
每个参数的初始值可能不同
，如果参数的初始值不同，使用
PFlash区存储就变得不现实，因为RAM区的参数位置可能会改变，所以
PFlash区无法一一对应RAM区的参数。怎么办呢？本文讨论一种可能性：

3、Application更新如何识别呢？
可以在NVM中预留一个指定地址（比如：0xAF0FFFFC），该指定地址存放Application的CRC值，如果Application有更新，则CRC更新，通过比对CRC可以知道Application程序是否更新，即使是裸版（从未刷写过Application程序），也可以通过比对CRC值，确认RAM区关键参数从何处读取更合适。
