诊断开发：采样点引发的连续帧错序问题

开心果 Need Car · 2022-11-08T10:12:00+08:00 · 微信原文

CAN总线中，采样点是一个容易被开发人员忽视的角色。如果不认真对待，可能会让"你"吃点苦头。本文，聚焦采样点不合理带来的一个工程问题，希望读到此文的朋友，能有所收获！关于采样点，前文讨论过，可以回顾前文CAN通信基础：采样原理。

问题描述

如上的数据流中，可以看出，CAN ID = 0x750的诊断报文在发送连续帧（CF：Consecutive Frame）的过程中，出现了序列号（SN：Sequence Number）错序的问题，即：0x2E和0x2F颠倒（如上图红框），正确的顺序应该先发送SN = 0x2E得CF，在发送SN = 0x2F的CF。

原因分析

数据log中，可以看出有大量的错误帧。错误帧和连续帧错序有关联吗？答：有。关于错误帧，不清楚的朋友可以参考前文CAN通信基础：错误帧。在进一步的分析错误帧可以看出，错误帧的CAN ID = 0x750，且错误帧产生在0x2E报文发送过程中，如下所示：

究其原因，需要先从本文的CAN配置说起：

1、Basic CAN配置

关于Basic CAN与Full CAN，可以参考前文CAN通信：Basic CAN与FIFO。本文中，将诊断报文配置成Basic CAN，且CanHwObjectCount ＞1。这意味着什么呢？答：意味着一个HTH（Hardware Transmit Handle）可以有多个硬件缓存区存。即：发送缓冲区的类型为 Tx Queue，如下所示：

2、CAN报文仲裁

我们知道，对于一帧CAN报文，能否发送到CAN BUS，取决于其是否能赢得内部竞争和外部竞争。关于CAN总线的仲裁原理，可以参考前文：CAN总线仲裁原理。对于CAN ID相同的报文，内部如何竞争呢？答：根据Buffer Index，即Buffer Index越小，发送优先级越高，具体解释如下所示：

3、错序的产生

0x750报文是如何产生0x2E和0x2F的错序的呢？如下所示：

Step1：连续帧2B、2C、2D、2E已经填充到硬件缓冲区，等待发送，由于CAN ID相同，发送顺序按照2B、2C、2D、2E所在的Buffer Index发送，Buffer Index越小，优先级越高。所以，连续帧2B、2C、2D依次发送；
Step2：发送连续帧2E的时候，发生了错误，总线产生错误帧，导致连续帧2E未发出，此时，上层又将连续帧2F填充到Buffer Index = 0的位置；
Step3：0x750再次赢得总线使用权，先将连续帧2F发送出去；
Step4：由于CAN总线的发送重试机制，连续帧2E重发，且发送成功，导致连续帧错序。

4、重传机制

11898-1中规定，当报文没有应答（acknowledged），或者出现错误帧时，可以使用LLC（Logical Link Control）自动重传机制（automatic retransmission），如下所示：

3
解决措施
如上分析，知道错误帧的重发导致错序，又是什么导致的错误帧呢？答：采样点设置不合理。需求要求采样点80%，实际设置采样点37.5%，导致数据采样不稳定，进而导致连续帧错序。
解决措施：修改采样点配置。
