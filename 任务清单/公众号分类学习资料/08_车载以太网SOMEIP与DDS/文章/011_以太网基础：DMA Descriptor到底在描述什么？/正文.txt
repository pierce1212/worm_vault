提示
：基于TC3xx讨论
1、DMA位置
在Ethernet的通信过程中，数据搬运由DMA负责。Ethernet使用专属的DMA Channel，不占用外设DMA模块的Channel。对于TC3xx，Ethernet最多可以使用4个Tx DMA和4个Rx DMA。发送数据时，DMA负责将目标内存区（Tx Memory）数据搬运到MTL（MAC Transaction Layer）的
Tx FIFO（最大4Kb），然后由MAC内核负责数据发送
；接收数据时，DMA将
MTL Rx FIFO（最大8Kb）
收到的数据搬运到接收内存区（Rx Memory），如下所示：
提示
：Tx FIFO或者Rx FIFO可由
多个队列（Queue）
共享
，TC3xx最多可以设置4个Tx Queue、4个Rx Queue。
每个Queue的大小必须是256 Byte的倍数
。
（一）Lwip中的DMA
熟悉Lwip(Light weight IP)的小伙伴，对如下流程应该不陌生。其中，DMA所处的位置如下所示：

首先，应用层（Application）将数据

其次，

Tx Memory数据到MTL Tx FIFO；
之后，
MTL Tx FIFO中数据被发送到总线。
如上三个过程属于异步行为
，且各自干活的
速率不同
。之所以速率不同，因为应用层搬运数据、MAC发送数据使用的Clock不同。
如果想让DMA按照预期方式干活，就需要告诉DMA如何干，也就是干活的规则，对于Ethernet数据的传输也不例外。不同于外设DMA模块，
对于Ethernet使用的DMA，CPU会将干活的规则放在
DMA Descriptor
中。
2、DMA Descriptors
对于TC3xx的DWC_ether_qos控制器，支持两种描述符（Descriptor）：
Normal
和
Context
。对于Descriptor，常使用链式结构（Link List）。
Normal Descriptor
：用于Packet数据和控制信息传输的描述。每个Normal描述符包含
两个缓存区（Buffer）和两个地址指针
；
Context Descriptor
：主要用于控制信息传输的描述。

3、Ethernet DMA初始化的软件实现
功能脱离不了代码实现，在TC3xx的用户手册中，也详述了Ethernet的DMA初始化步骤，本文，结合Code，分析一下Ethernet DMA初始化关键点的实现。
（1）
Software Reset
，主要操作DMA Bus Mode Register的SWR位域，以便于完成DMA, MTL和MAC内部寄存器复位，当完成DWC_ether_qos Clock的复位动作以后，
此位域自动清零
。DMA_MODE寄存器的软复位动作如下所示：

void

gethSFR->DMA_MODE.B.SWR =
1

（2）
在进行后续的DMA, MTL和MAC配置之前，需要等待复位完成，即，直到
gethSFR->
DMA_MODE.B.SWR
== 0
