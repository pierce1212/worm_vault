汽车嵌入式开发中，想必大家对*.dll文件并不陌生，诊断的$27服务，标定时的解锁都会用到*.dll文件。很多时候，*.dll文件的提供需要依赖底软开发人员，标定工程师/诊断测试工程/EOL产线人员需要*.dll文件时，总的找人制作*.dll。本文讲讲怎么基于Visual Studio做一个可用的*.dll文件。
1
为什么需要*.dll文件
先看一下百度百科对*.dll文件的定义：
*.dll文件是一个库文件，说白了就是人家只想给你用，不想告诉你算法。在我们汽车的嵌入式开发中，诊断和标定这两项工作都需要一定的安全级，不能任何人都能对车辆“动手动脚”。比如：车辆故障了，去检修，需要通过诊断仪对故障信息读取，维修好以后还需要清除对应的故障，这些操作只希望有对应权限的人操作，怎么知道其是否有这样的权限呢？告诉ECU“口令”，即：ECU校验算法计算的Key。为了算法不被外人知道，OEM会将算法加密，做成*.dll文件，授权给目标人员。同样，对车辆标定时，由于修改的数据都是const常量，且这些数据多数涉及车辆的性能，所以，这些数据 的修正工作也必须验证操作人员的合法性。
怎么计算$27 服务的随机种子和Key，前面聊过，大家可以回顾
Uds诊断：$27服务，ECU如何产生随机种子
。
既然，*.dll文件如此重要，那谁来做呢？实际项目开发中，一般会由底软工程师提供，底软工程师一般会有OEM的具体算法需求。做标定的工程师会提供标定用的*.dll文件，主要给INCA或者CANape等标定工具使用；做诊断开发的工程师会提供诊断用的*.dll文件，主要给类似Canoe等上位机软件使用。
但是在实际的开发中，多数软件工程师不清楚如何制作*.dll文件，或者制作的*.dll文件给到他人时，不能用。

3
源文件的编写
制作*.dll源文件本身不难，难点是很多工程师不会编写源文件，以及如何将百度得到的文件改写。这里，给大家提供可用的模板，大家可以基于此源文件改写，适配自己的工程项目。
源文件分为诊断用文件和标定用文件，也可以将两部分功能合到一起，制作一个*.dll文件，同时给诊断、标定使用。
1、诊断源文件
SeedKey.h文件内容如下所示：

SeedKey.c
文件内容如下所示：
#include <windows.h>
#include "SeedKey.h"
static const unsigned char EOLCodeDefault[EOL_CODEDEFAULTLENGTH] = { 0x11, 0x22, 0x33, 0x44 };
EOL_SEEDKEY_API VKeyGenResultEx GenerateKeyEx(
const unsigned char* iSeedArray,
unsigned int iSeedArraySize,
const unsigned int iSecurityLevel,
const char* iVariant,
unsigned char* ioKeyArray,
unsigned int iKeyArraySize,
unsigned int* oActualKeyArraySize)
{
if (iSeedArraySize > iKeyArraySize)
{
return KGRE_BufferTooSmall;
}
for (unsigned int i = 0; i < iSeedArraySize; i++)
{
ioKeyArray[i] = (~iSeedArray[i]);
}
for (unsigned int index = 4; index < iSeedArraySize + 4; index++)
{
ioKeyArray[index] = EOLCodeDefault[index - 4];
}
*oActualKeyArraySize = (unsigned int)EOL_RESPONSEKEYLENGTH;
return KGRE_OK;
}

上位机发送0xF8命令，ECU正响应以后，回复的报文中告知种子的长度。上位机通过接口函数XCP_ComputeKeyFromSeed中的参数ByteLengthSeed，即可获得ECU给的种子长度。
接口函数XCP_ComputeKeyFromSeed 中，参数PointerToSeed指向种子位置；参数ByteLengthKey指向上位机要回复Key长度的位置; 参数PointerToKey指向上位机要回复Key值的位置
