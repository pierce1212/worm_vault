Tasking基础，为什么常量无法放到指定内存区？

开心果 Need Car · 2025-04-07T06:36:00+08:00 · 微信原文

如何使用Tasking编译器将变量放到指定内存区，之前讨论过，可以参考前文《Tasking基础：将常量放入指定PFlash位置》、《Tasking基础：将变量放入指定内存的两种方式》。本文聚焦Tasking（版本：6.2.2）使用中的另一个问题：明明在*.c和*.lsl文件中定义了段（section），但是，对应的变量并没有出现在*.map文件指定内存中，为什么呢？

1、*.c和*.lsl文件修改

如果要将常量放到指定内存，我们需要做两件事：
（一）*.c中定义常量
*.c中定义常量，并且将该常量放到自定义段（本文自定义段为DebugPassword）中，示意如下所示：
#pragma section farrom "DebugPassword"const bl_u32_t Debug_Password[8]= {    0x00000001,     0x00000002,     0x00000003,     0x00000004,     0x00000005,     0x00000006,     0x00000007,     0x00000008};
（二）*.lsl文件定义段
在*.lsl文件定义段（本文自定义段为DebugPassword），并指定该段的起始地址为0xA0010000，示意如下：
......group(ordered){    group DebugPassword(run_addr=0xA0010000)    {        select "*.DebugPassword";    }    ......}......
如上操作以后，是否能将常量Debug_Password放到起始地址为0xA0010000的位置呢？答：实际并没有。为什么呢？

2、为什么常量没有放入指定内存

实际使用编译器的时候，我们会进行编译优化设置，在链接阶段，一般勾选"Delete unreferenced sections"选项，即：删除未用到的Section。具体位置如下：
这项优化会从生成的对象文件中删除未被引用（reference）的Section，也就是说：虽然函数或者变量定义了段，但是该段内的函数和常量没有被引用，编译器将自动删除该段。主要是为了减小生成的代码尺寸，所以，函数和常量也不会放入指定内存。
既然如此，直接关闭"Delete unreferenced sections"选项是否可以呢？不推荐，那么，如何解决呢？

3、解决措施

既然编译器会删除未引用的段，如何使得编译器不删除目标函数或者变量呢？（变量未被引用，但是并不代表不会使用），本文讨论两种解决方案：
（一）在对应的常量后增加保护属性__attribute__((protect))
#pragma section farrom "DebugPassword"const bl_u32_t Debug_Password[8] __attribute__((protect))= {    0x00000001,     0x00000002,     0x00000003,     0x00000004,     0x00000005,     0x00000006,     0x00000007,     0x00000008};
提示：添加关键词“farrom”修饰，主要是为了在自定义段前添加前缀.rodata，相关修饰符描述如下所示：

（二）使用#pragma protect/endprotect
另一种表达形式如下所示：
#pragma protect#pragma section farrom "DebugPassword"const bl_u32_t Debug_Password[8]= {    0x00000001,     0x00000002,     0x00000003,     0x00000004,     0x00000005,     0x00000006,     0x00000007,     0x00000008};#pragma endprotect
