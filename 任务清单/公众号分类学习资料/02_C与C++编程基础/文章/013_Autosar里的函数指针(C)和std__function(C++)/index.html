Autosar里的函数指针(C)和std::function(C++)

开心果 Need Car · 2021-11-19T20:52:00+08:00 · 微信原文

前期

       嵌入式的开发过程中，C和C++是使用最多的两种语言，两种语言的优劣见仁见智。本文想聊一聊C的函数指针和C++的std::function，在我们码代码的过程中，想必只有踩过坑，写过几个Bug的程序员才能对这两者体会的更真切。

C的函数指针

       什么是函数指针？函数指针是指向函数的指针变量 。具体定义格式如下所示：

函数返回值类型 (* 指针变量名) (函数参数列表)

       举一个具体的定义示例：

int(*funPtr)(int, int)

      这里的funPtr就可以像平时定义的指针变量一样指向一个函数，该变量用来存储一个地址，对于函数来说，函数名就是这个函数所在的地址。如下是函数指针使用的一个示例：

int addFunc(int x, int y)

{

   return (x+y);

}


int main()

{

   int localVal = 0x00;

   int(*funPtr)(int, int);

   /*将函数addFunc地址赋给函数指针变量funPtr*/

   funPtr = addFunc;


   localVal = funPtr(5,6);

   getchar();

}

        运行结果：
11
      说到这，函数指针似乎没有什么不可理解的，但是要把它用好和理解是几个例子所不能体现的。接下来我们说一说在开发设计和Autosar中，函数指针是如何体现它价值的。
       在CP Autosar中，函数指针在各个模块均有体现，比如：CANSM模块中，如下是CANSM模块中一个结构体声明的一部分。

typedef void (*CanSM_CbkFuncType)(struct CanSM_ChannelTypeTag *pCh);


typedef struct CanSM_ChannelTypeTag

{

/* Timer or Polling main function */

CanSM_CbkFuncType pBORMainFnc;

/* bus-off recovery time out function */

CanSM_CbkFuncType pBORTimeoutFnc;

/* bus-off recovery function */

CanSM_CbkFuncType pBusOffFnc;

   ......

      使用函数指针有什么好处呢?使用函数指针给开发人员预留了拓展模块功能的可能性。当我们想增加某个功能时，只需要将此回调函数打开，写一个实现功能的函数即可，这样做不仅不破坏原有的代码框架，而且在查找问题的时候更好定位。具体说，原有的框架是经过市场和多个项目检验的，如果开发人员新增的某个功能不符合预期，去查实现的功能函数即可，而不必大费周章的将模块所有部分追查一遍。
       如下，如果不想拓展功能，给一个空指针即可，如果拓展功能，将对应功能函数名称填充即可。

......

CanSM_RunTime[netLoop].pBusOffFnc = NULL_PTR;

CanSM_RunTime[netLoop].pBORTimeoutFnc = NULL_PTR;

CanSM_RunTime[netLoop].pBORMainFnc = NULL_PTR;

......

       这其实给我们开发人员一个很好的提示，在我们设计代码架构的时候，要充分考虑代码的移植性和拓展性。移植性要求我们写的代码更通用，低耦合高内聚，而拓展性则需要我们预留一定的“后门”，不能说在此模块上增加一个功能就无法实现，或者打补丁实现，这样使得原有代码框架不断的变“胖”，这样代码还怎么“美”？而拓展性的实现一般可通过预留函数指针实现。
C++的std::function
       如果说函数指针在CP Autosar中能大显神威，AP Autosar中哪个门神又能和它一较高下呢？个人觉得std::function可以与其PK一番，甚至可以直接KO。
        举一个例子，如下所示：

#include <iostream>

#include <functional>

/* 声明一个模板 */

typedef std::function<int(int, int)> comfun;


/* 定义函数 */

int addFun(int a, int b) {return a + b ;};


int main()

{

   comfun funPtr = addFun;


   std::cout<< funPtr(5, 3) << std::endl;


   return 0;

}

        运行结果：
8
       可以看出，通过std::function起一个别名和函数指针类似，而这里更方便，可以使用comfun定义指针，感觉就像使用了一个指针变量。
        将上述代码在升级一点，如下所示：

#include <iostream>

#include <functional>

/* 声明一个模板 */

typedef std::function<int(int, int)> comfun;


/* 定义函数 */

int addFun(int a, int b) {return a + b ;};


int paly(comfun Pfun, int x, int y)

{

   return Pfun(x,y);

}


int main()

{

   std::cout<< paly(addFun, 5, 3) << std::endl;


   return 0;

}

        运行结果：
8
       这里将comfun看作一个数据类型，作为函数的形参使用，是不是感觉这样写代码有点任我行的感觉。而这恰恰是AP Autosar最得瑟的地方，看一下Someip的部分开源代码，如下所示：

......

typedef std::function< void (service_t, instance_t, bool) > availability_handler_t;

typedef std::function< bool (client_t, bool) > subscription_handler_t;

typedef std::function< void (const uint16_t) > error_handler_t;

......
       因此，好的代码框架会充分考虑代码的移植性和拓展性，而这也恰恰是值得我们开发人员学习的地方。好的开发人员不是比谁写的代码多或者工作年限久，而是看其能否设计好的代码框架，代码框架的层次结构是否合理，而这也是我不断鞭策自己的驱动力。
