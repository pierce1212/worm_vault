如何安全的存储和获取Debug password

开心果 Need Car · 2025-08-07T06:32:00+08:00 · 微信原文

随着车载信息安全的发展，各家Tirer 1或者产品公司越来越注重产品的防护。其中，最典型的防护措施之一就是调试口（debug interface）的防护。即：为每个生成的产品（比如：控制器）设置唯一的Password。而且，产品一旦离开企业的生产线（Production Line），调试口将会被disable，即：去除硬件调试口。而且，调试口的焊点散落在PCB不同位置，在没有原理图的情况下，将不可辨识。
设想这样一种场景：4S店或者企业工厂需要对问题产品或者保修设备(Warranty device）进行维修。此时 ，需要借助调试器调试分析问题件。如果产品想重新连接调试口使用，需要面临两个问题：
1、如何获取该产品的唯一Password?
2、如何确保获取Password的人员是授权的？

1、如何存储Password

获取Debug Password之前，我们需要思考如何存储Debug Password。为了最大限度的确保Debug Password的安全，需要设计一套有效的方案。
（一）Debug Password存储的一种方案
每个产品在产线端使用HSM自带的TRNG（True Random Number Generator，真随机数发生器）生成随机的Debug Password（eg：16 bytes），并且将该Debug Password存储到UCB（User Configuration Block）或者其他可以存储Debug Password的位置（eg：PFlash）。此时，无人知道Debug Password是什么。
企业通过内部服务器生成非对称密钥对（eg：RSA2048），使用公钥对生成的Debug Password加密（提醒：公钥加密），之后通过UDS服务，将加密后的Debug Password存储到离线的存储设备。至此，谁也不知道Debug Password是什么。
（二）获取Debug Password
将Password直接告诉对应工程师可以吗？从信息安全的角度考虑，存在一定的风险，即：无法确认获取Password人员的身份合法性，可能会导致产品机密信息外泄。所以，为了尽可能的保护公司资产，即使工厂产线端，获取Debug Password时，也需要通过公司的内部服务器获取，进行身份认证，而且debug Password需要加密传输。
获取产品唯一的Debug Password，需要经过如下几个步骤：
  1. 首先，通过产品序列号到离线存储设备查找加密的Debug Password。这一步必须是公司授权的人员有权限访问该设备；
  2. 获取到加密的Debug Password以后，需要公司授权的人员登录公司内部服务器，使用对用的私钥（private key）解密；
  3. 成功解密后，即可获取该产品唯一的Debug Password，之后即可进行产品的调试。
在步骤1~2中，需要访问人员具有合法的权限，方能登录设备获取信息。这就确保了操作人员的合法性，所以，不是公司内部员工，将无法获取对应的权限。而且，每次访问，服务器会记录是谁访问的信息。
Debug Password使用公钥（public key）加密传输，确保了数据传输的机密性。
