1、如何确保伪随机数不可预测？
PRN由PRNG（Pseudo Random Number Generator，伪随机数生成器）产生。虽然是生成伪随机数，但是，也需要确保随机数的不可预测性。那么，如何确保生成的随机数不可预测呢？
PRNG产生随机数的核心是种子（seed）的产生，具体说，由尽可能大的熵（
entropy
）产生seed。为什么要确保生成的熵值尽可能的大
呢？
熵值在随机数中表示随机变量的不确定性，熵值越大表示不确定性越高，反之则不确定性越低
。
举例说明
：熵值由二进制0和1表示，一个bit位有2^1可能性；两个
bit位有2^2可能性；三个
bit位有2^3可能性...以此类推。bit位越多，数值越大，不可预测性就越高。
既然
熵可以
衡量系统中的不可预测性，且越大越不可预测
，那么，熵值应该取用多大合适呢
？eg：≥80 bit的
entropy。那么，谁能产生这样的熵呢？真随机数生成器（TRNG，True Random Number Generator）。因为TRNG产生的随机数是由物理过程
（eg：热噪声）
产生的。所以，可以认为其产生的随机数均是不可预测的。因此，
PRN（伪随机数）由TRNG产生的熵（＞80 bit entropy）作为Seed，进一步地去产生伪随机数
。
代码示意如下：
/* 1、真随机数生成器（TRNG）产生80 bit的entropy */
HSM_generateTRN(
uint32
* entropy ,
uint32
len
);
/* 2、使用不可预测的entropy作为seed */
srand(*entropy);
/* 3、生成伪随机数 */
for
(
uint16
i =
0
; i < Len； i++)
{
ptrn[i] = rand();
}
2、Timer或者ADC等适合作为熵源吗
之前，聊过System Timer作为srand()函数的seed，即：产生熵值。但是，在32 bit带宽的单片机中，
System Timer长度仅仅只有32 bit或者64 bit（两个32 bit寄存器）。这个长度的熵（
entropy
）并不能满足工程要求（eg：至少80 bit）。
而且Timer产生的熵值要么递增，要么递减，具有预判性
。
同理，A
DC（
Analog-to-digital converter
）也很难满足熵值长度和不可预判性的要求。
所以，从信息安全的角度考虑，伪随机数的熵源，使用Timer或者ADC并不适合。最理想的方案就是使用H
SM（
Hardware Security Module
）
产生的真随机数（
eg：生成128 bit真随机数
），因为HSM产生的真随机数，由物理过程产生，且产生过程不可预测。
这是不是就感觉有点“多此一举”？既然最终目的是获取随机数，为什么不直接使用HSM生成真随机数呢？确实如此。但是，工程项目，问题千奇百怪，以尽可能满足客户诉求为目标。如果所用芯片不支持真随机数，那么，使用Timer或者ADC等硬件产生熵值也并非不可接受。
