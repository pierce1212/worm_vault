对于目前的车载软件升级，待升级软件的真实性靠“验签”这个动作保证。而软件升级的验签往往使用非对称算法，其中RSA2048就是一个典型的例子。当然，有的小伙伴可能会说，RSA2048已经被证实不再安全，使用ECC（
Elliptic Curve Cryptography，椭圆曲线密码学）
算法更稳妥。确实，我不否认这个事实，但是，对于我们工程项目，需要考虑的因素很多，技术只是工程项目需要考虑的一个因素。虽然RSA2048有它的问题，但是，在未来的一段时间内，它依然会是软件验签的主角。所以，在新晋替代者还没有规模化使用前，搞懂现有的算法，依然是工程师的“基本功”。
对于验签动作，往往不是单一密码学算法的讨论，而是多种密码学的组合：本文基于
RSA2048+
SHA-256+PSS（Probahuibilistic Signature Scheme）
展开讨论。
彻底理清这三个算法如何进行软件签名和验签流程
。
1、RSA2048+SHA-256+PSS通识
对于RSA，目前主要参考
IETF（
Internet Engineering Task Force，
互联网工程任务组
）发布的
《RFC 8017 - PKCS
#1
: RSA Cryptography Specifications Version 2.2》
规范，这也是多数项目中要求参考的规范。
IETF是一个开放的国际性组织，
通过发布RFC（Request for Comments）文档来定义标准。
（一）RSA2048
RSA2048（
Rivest–Shamir–Adleman
）算法对应的
密钥长度
2048 bit（256 bytes），需要公、私钥配合使用。
（二）SHA-256
SHA-256
（Secure Hash Algorithm）可以对
任意输入长度
数据生成
256 bit固定输出
。
（三）PSS填充
对于RSA2048非对称算法，通常使用
PKCS（Public-Key Cryptography Standards）
#1
v1.5 或者PSS
填充模式
。
PKCS
#1
v1.5
RSASSA-PSS
全称
Public-Key Cryptography Standards
#1
Version 1.5
RSA Probabilistic Signature Scheme
填充方式
固定填充
（EMSA-PKCS1-v1_5）
概率性填充
（EMSA-PSS）
随机性
无（确定性签名）
有（使用随机盐）
抗攻击能力
容易受到填充攻击
抗篡改能力强，防止多种攻击
由于
PKCS
#1
v1.5的填充方式固定，安全性弱，所以，对软件签名时，往往使用安全性更高的
RSASSA-PSS填充方案，以此确保：
即使相同的明文，每次生成的签名值不同
。
所以，对于RSA的软件验签，其实是讨论
非对称算法
、
hash值
以及
填充模式
组合的问题。
2、RSA2048+SHA-256+PSS签名验签原理
（一）签名流程
RSA2048+SHA-256+PSS签名流程如下所示：
具体的签名流程：
1、为了加速签名流程，首先使用SHA256对原始的软件数据进行hash计算，得到mHash；
2、生成随机的盐值（32 bytes）。
注意：
推荐的盐值长度等于哈希函数的输出长度
。
使用SHA256计算时，输出的固定长度是32 bytes，所以，对应的盐值长度也必须是
成32 bytes
。
3、对Pad(8 bytes的0x00)+mHash(32 bytes)+Salt（32 bytes）进行二次SHA256计算，得到H；
4、将PS+0x01+Salt组合成DB值；
5、
H作为MGF1()函数输入
，
得到的输出与DB进行
异或
操作
，得到MaskedDB；
6、
MaskedDB+H+0xBC(截断符号)组合成EM，至此，
完成了
Encoding Operation（编码操作）
，即：
EMSA-PSS-ENCODE。
之后，使用
私钥
对EM进行
签名计算
，得到
签名值
EM'（长度256 bytes）;
提示：
RSA私钥有两种表示形式，
如果使用简单的表示形式
，
私钥签名和加密的数学处理一样
，均符合 result = m^d mod n，此时的签名可“看作加密”。本文基于私钥简单形式讨论，即：私钥（n,d）。
7、发送端将
签名值EM'
连同
原始数据
发送到接收端，注意：RSA2048对应的公钥提前灌装在接收端。
补充：
RSA是基于
大整数数学
的非对称加密算法。当使用2048位密钥（即 256 字节）进行加密时，
无论加密的原始数据有
多小
，
加密后的密文长度始终是256 字节
。
这是因为RSA加密的结果是一个模n的大整数
，n是密钥的一部分，其长度就是密钥长度。
以PKCS
#1
v1.5 填充为例，
最大可加密数据长度 ≈ 密钥长度 - 11 字节，
对于2048位密钥：最大明文长度 ≈ 256 - 11 = 245 字节；
RSAES-OAEP（加密），
最大加密长度：k−2hLen−2字节（k是密钥长度，hLen是哈希输出长度）。
RSA2048加密后的数据是一个固定长度的256字节的字符串（
本质上是一个二进制数据块
），
这个字节串可能包含不可打印字符
，比如 \x00, \xFF，甚至控制字符。
一般需要进行
Base64 编码
，让其可以变得安全、可读、可传输。
Base64 会把不可见的字节转换成可打印的字符
。
（二）验签流程
1、使用RSA2048对应的公钥对EM'进行解密，得到
EM；
2、判断EM的截断符号0xBC是否正确，如果正确继续处理，否则，验签失败；
3、提取
MaskedDB和H，为了便于区分，这里标记为
MaskedDB_R和H_R
；
4、使用MGF1()函数对
H_R进行计算，得到的结果与
MaskedDB_R进行异或操作，得到DB' ，期望DB'= PS+0x01+Salt_R；
5、判断收到的PS和0x01是否符合预期，符合继续处理，否则，验签失败；
6、对收到的明文进行SHA256计算，得到mHASH'，Pad+
mHASH'+
Salt_R构成M'，对M'进行SHA256计算，如果
SHA256（M'）==
H_R，验签通过，否则，验签失败。
拓展补充：
有人说，私钥加密，公钥可以解密；公钥加密，私钥可以解密。有啥区别呢？注意，如果使用私钥加密，那么凡是持有公钥的第三方均可以解密，不管这个第三方是否合法。这也意味着，信息可能被泄露。
